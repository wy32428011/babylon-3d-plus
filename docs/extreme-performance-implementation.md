# 极致性能优化实施与验收记录

本记录对应仓库根目录的 [极致性能优化方案](../极致性能优化方案.md)。设计基线为 `82b8c80`，实施日期为 2026-09-11。本文区分代码实现、隔离回归、实际场景测量和尚未完成的验收，不能将其中一类结果替代另一类。

## 实施边界

项目与本地场景的模型同步、来源/修订校验、环境、天空盒、合批和完整首帧门控保持原流程。没有修改场景格式、模型包、参数化脚本、动画资源、Stacker/Conveyor/RGV 驱动算法、画质或分辨率。

当前源代码与旧文档关于“每次中台打开是否强制下载全部模型”的描述存在差异。本次不更改下载策略，不合并同步前后的两次独立远端确认，也不以缓存命中跳过原有强制刷新分支。

## 已落地的改动

| 方案项 | 改动 | 兼容与资源边界 |
| --- | --- | --- |
| M0 / O1 | 性能报告增加真实渲染帧间隔及 P50/P95/P99；模型脚本初始化区分排队和同步执行时间 | 逐帧采集仅在性能运行/Viewer 诊断开启；固定容量、最近一分钟；复制时排序，普通运行不增加逐帧观察器 |
| M1 / O2 | `editor-asset` 使用独占 ArrayBuffer 的有界字节流，减少 Node→Web 通用适配器的额外复制 | 原有文件授权、404/403、ETag/304 和内容类型保持；长度提示只减少分配，仍以实际 EOF 结束；取消关闭对应文件句柄 |
| M2 | 基础性能历史继续低频采样，材质/包围盒等详细统计按 HUD 是否展开采集 | 隐藏 HUD 不丢失基础历史；不改变渲染内容或运行帧频 |
| M3 / R1 | 静态碰撞索引复用，几何内容、索引数组、世界矩阵、显隐、移除和场景代次变化可靠失效 | 不减少碰撞半径、三角预算或物理子步；几何监听共享并按引用释放，保留原有应用回调 |
| M3 / R2 | 邻域先保留有序三角引用，候选未变时复用代理；仅候选变化时展开坐标 | 保留原有格子、网格、三角与预算截断顺序；相同代理数据不重复上传或计算法线 |
| M3 / R4 | 没有手动漫游 POI 的编辑场景不预加载默认人物；退出漫游暂停正在播放的内置片段，重进恢复原动画实例 | 增加 POI、显式更换人物或首次启用时仍走原加载流程；不重置片段进度，不重启已结束的跳跃，不改变可见状态下的倍率和动画频率 |
| M4 / T1 | 遥测帧增加候选准备、上下文、驱动、阵列刷新、外部货物、诊断清理、基线和告警的分阶段计时 | 不改变上下文注入与驱动先后顺序；未开启计时时不读取高精度时钟；子阶段不能再与总耗时相加 |

渲染帧间隔指 `scene.onAfterRenderObservable` 回调之间的时间，包含帧间主线程等待；它与 GPU 帧耗时、显示器最终呈现时间不同。原有 1 Hz 样本分位数继续保留，新报告的 `frameTiming` 单独提供逐帧结果。停止编辑器性能运行后报告冻结，新场景/新会话重新开始。

## 基线与归因证据

当前测试机器为 Intel UHD Graphics 630，真实 WebGL 2 / ANGLE D3D11。探索阶段使用 1440×900 窗口；按用户确认，最终配对验收改为 3840×2160 全屏、DPR 1，并重新采集同尺寸原版基线。编辑器面板占用的区域不会计为 3D Canvas，报告分别记录窗口、实际 Canvas、相机、资源修订与参数清单哈希。目标项目为“中鼎智能工厂”，初始场景约 370 个实体；运行时模型数和合批实体数分别记录，不能机械相加推算逻辑实体总量。

- 实际中台打开探索：冷资源打开 `92,148 ms`，重复打开 `92,665.7 ms`，两次均通过完整加载就绪。重复打开天空盒解码已命中缓存，因此不能把“再加天空盒缓存”当作新的主要方案。两个样本不能作为可靠 P95。
- Renderer profile 中，脚本内部节点查询、纹理上传和材质更新占用明显。静止在线试跑中 `collectModels` 自身仅约 `3.5 ms / 10 s`，当前没有证据支持为这一小项引入复杂的跨帧注册表。
- 漫游试跑约 `2.2 FPS`，约 5 秒的 CPU profile 中 `indexMesh` 占约 `2.7 s`；邻域三角展开、法线生成也存在重复工作。正式原版漫游三轮约 `2.1–2.7 FPS`；部分窗口 CPU 帧耗时约 `340–424 ms`，GPU 约 `18–22 ms`，支持优先处理碰撞 CPU 开销。
- 已录制当前项目真实 MQTT 消息：70 秒捕获中有 1,334 条与场景匹配的消息，包含动作信号。回放保留原始 payload、源时间和顺序，并只在 loopback Broker 投递；不向实际 Broker 发布控制消息。
- 75.6 MB EXR 的隔离传输测试中，Electron 自带运行时的中位耗时约从 `396 ms` 降至 `303 ms`，文件 SHA-256 一致。普通 Node 下收益不明显；这项结果不能直接当作完整打开耗时的提升。

所有报告保存在 `output/playwright/extreme-performance/`。失败的夹具试跑保留为失败记录，不计入验收。早期跨漫游后的编辑态取样存在相机复位顺序问题，已修正；这类编辑态样本由修正后的原版工作树回放补测替代。

## 验证工具

### 原有入口

- `npm run test:scene-loading`、`npm run test:local-scene-recovery`、`npm run test:unified-model-sync`：对应的资源、同步、就绪与恢复契约。
- `npm run test:telemetry`：遥测、驱动、货物与相关模型回归。
- `npm run test:telemetry -- telemetryFrameCaching.test.ts`：选择明确测试文件；不改变默认全套行为。
- `node scripts/smoke-real-project-loading.mjs --url <中台地址> --project <项目名称> --cold 3 --warm 10 --profile`：实际中台打开及 CPU/资源时序。

遥测运行器仅在临时编译产物中补全 Babylon 深层 ESM 导入，并在子命令失败后执行清理、保留退出码，不改动生产源码的导入语义。

### 新增入口

```powershell
# 资源流的隔离吞吐与完整性比较，不修改输入文件。
node --experimental-strip-types scripts/smoke-asset-stream-throughput.mjs "完整资源路径"

# 使用场景副本、本机回放 Broker 和正式打开/运行/漫游入口。
node scripts/smoke-extreme-scene-performance.mjs `
  --scene "完整场景路径.scene.json" `
  --workspace "资源工作区" `
  --url "中台地址" `
  --output "output/playwright/extreme-performance/my-run" `
  --seconds 60 --repeats 3
```

`--replay` 接受本地录制文件；录制必须覆盖预热与完整采样时间，不能把录制耗尽当作静止。`--app-root` 可指定单独构建的基线应用。`--fullscreen` 要求实际 4K 全屏；采样期间改变 Canvas 尺寸或固定组相机将使该次测试失败。`--no-timing` 关闭额外遥测阶段计时，用于观察诊断扰动。原始报文只保留在本地忽略目录，不写入性能摘要或提交。

`optimized-runtime-full` 在执行中发生画布与相机变化，已标记为无效，不能与 1440×900 的基线比较。后续仅使用固定条件的成对结果。

## 回归状态与已知基线问题

已完成的定向回归包括静态索引复用、同顶点数几何更新、索引/变换/显隐更新、共享监听释放、邻域复用、场景切换清理、人物延迟加载与过期请求、逐帧采样/窗口/冻结、资源字节与 EOF/取消、MQTT 实际订阅和回放顺序。

较宽的遥测测试执行得到 239 项通过、3 项失败。对应三项在独立 `82b8c80` 工作树中同样失败，分别涉及环境单位的旧期望、场景序列化源码格式断言、天空盒测试自身的嵌套编译依赖路径。这些不是本次性能修改产生的新失败；本次不更改环境单位策略或序列化格式来迎合旧断言。

加载套件 `161/170`、本地恢复 `57/64`、统一同步 `106/112`。失败集合均落在已用原版工作树复现的 9 个用例中：资源准备测试的导入问题、旧 UI/源码结构断言，以及天空盒测试缺少 `shouldValidateSceneModelResources` 上下文。保留这些失败，不能将套件写成全绿。

追加的定向组合回归 60 项全部通过（运动输入、碰撞、逐帧窗口、字节流、回放及报告）；此前定向遥测/驱动/货物回归 149 项通过。测试集合有重叠，不能相加后宣称互不重复的总覆盖数。

人物集成通过导入、同名副本、损坏/外部引用拒绝、SOURCE ZIP、Viewer 路径改写与 sandbox preload。默认/自定义/失败占位人物的 WebGL 遮挡六种组合通过；首次运行因开发测试模块加载超过 60 秒失败，临时测试副本延长模块加载等待后通过，未调整任何像素断言或 FPS 门槛。

独立测试项目完成 10 次 A→首页→B 循环，发布上下文、项目根目录和资源列表均按会话清理，无页面错误。可复跑 `node scripts/smoke-project-session-close.mjs --cycles 10`，脚本已按当前来源隔离目录校验。此结果是当前 Electron 的测试项目隔离验证，不能冒充真实中台项目的全部业务验收。

打包版远端场景回归通过 11 项检查，覆盖连续加载、历史来源重绑定、普通/组合/环境全库同步、最新参数定义与原实例值、幂等/撤销/重做、本地差异备份、真实下载 404 后原快照可编辑、资源提示关闭/重开及恢复重试。原脚本的旧参数定义断言已在原版复现，现有脚本按当前策略修正；404 使用未缓存的新修订，不删除有效缓存、不把同修订缓存命中误判为未报错。命令为 `node scripts/smoke-packaged-remote-scene.mjs "打包 exe 路径"`。

另一个旧的 Viewer GPU 源码正则要求字面量 `requireHardwareAcceleration: true`，而当前基线已通过受控函数计算该值，因此原版/优化版均在该旧断言失败。本次未修改相关 GPU 策略；真正的 Viewer 浏览器检查确认使用 Intel 硬件 renderer，没有使用软件回退。

## 按测量结果保留原实现的项目

| 候选 | 当前决定 | 原因 |
| --- | --- | --- |
| 跨打开跳过工程包/强制资源下载 | 不纳入 | 会改变原策略，且不能仅凭版本或路径存在认定内容可信 |
| 统一扩大所有加载并发 | 保留现有预算 | 当前受脚本初始化、GPU 上传等共同影响，缺少支持扩大并发且不提高峰值内存的证据 |
| 重新建设天空盒 Worker、模板缓存、合批或空间分片 | 不重复实现 | 当前已经存在并在实际加载中使用 |
| 候选注册表、JSON Path Worker、大范围快照缓存 | 暂不扩大 | 本次实际 profile 中未成为主要成本；优先保持同帧绑定变化、复杂值和事件边沿语义 |
| 代理模型、删面、降低 DPR/纹理/阴影质量 | 不采用 | 不满足本方案的画面与资源完整性约束 |
| 改写参数化脚本内部节点查询和设备动画算法 | 不采用 | 属于方案明确保护的实现；其剩余成本必须如实披露 |

## 最终验收

### 4K 场景配对测量

使用编辑器原有“全屏显示场景”入口，窗口目标 3840×2160，实际 Canvas 固定为 3840×2110（顶部保留工具栏）、DPR 1。Windows 全屏边界出现过 1 px 高度变化，因此测试副本固定 Canvas CSS 尺寸，原版与优化版应用相同设置。生产界面的尺寸策略没有改变。

原版和优化版各完成 7 组 × 3 轮 × 60 秒；所有报告通过，源场景未改动，模型/参数清单、相机、回放哈希与画布尺寸一致。这里的 FPS 和 P95 均为三轮中位数，P95 来自各轮真实逐帧间隔，不能理解为合并总体 P95。

| 状态 | 原版 FPS | 优化版 FPS | 原版 P95 ms | 优化版 P95 ms |
| --- | ---: | ---: | ---: | ---: |
| 编辑态 | 9.71 | 9.83 | 111.7 | 124.1 |
| 静止在线 | 10.32 | 8.68 | 117.0 | 123.5 |
| 真实数据、动作关闭 | 9.99 | 9.08 | 112.7 | 120.5 |
| 完整动作 | 9.92 | 10.08 | 118.8 | 117.5 |
| 静止漫游 | 2.50 | 9.24 | 487.0 | 152.2 |
| 行走漫游 | 2.57 | 9.31 | 479.4 | 151.6 |
| 动作与漫游 | 2.49 | 8.82 | 494.3 | 157.8 |

三个漫游组的 FPS 中位数增加约 254%–269%，P95 下降约 68%。三轮静止漫游的索引建立与代理上传计数在完整采样段内均未增加，满足初始化后不重复重建/上传的结构性要求。

**测量限制：** 优化版取样期间发现其他 Node、grok、Java 进程有较高 CPU 占用，未停止这些非本任务进程。因此上述静止在线、仅接收数据组的下降不能直接归因为代码，也不能忽略。

关闭阶段计时后，对两组补采原版/优化版各三轮 60 秒。静止在线中位 FPS 为 `10.356 → 10.406`，P95 为 `118.8 → 115.8 ms`；仅接收数据为 `10.381 → 10.406 FPS`，P95 为 `114.1 → 113.0 ms`。普通运行未重现持续退化。这组数据保存在 `baseline-4k-no-timing`、`optimized-4k-no-timing`、`4k-no-timing-comparison.json`。由于分批采样期间系统并发负载没有完全控制，不能用前后两组差值精确推算新增诊断的净开销；正式性能验收仍建议在稳定负载下复核诊断开关扰动。

证据：`output/playwright/extreme-performance/baseline-4k-fixed/result.json`、`optimized-4k-fixed/result.json`、`4k-comparison.json`。可用 `scripts/compare-extreme-scene-performance.mjs` 重新核对配对条件并汇总。

本节下方列出的资源、Viewer、保存重开及生命周期验证已经完成。当前未达到目标机器 4K 场景的 30/60 FPS 门槛；代码回归通过或单项漫游改善不等于方案的全部性能验收目标已经达成。

### 资源、Viewer 与生命周期

- 真实工厂副本通过正式“保存场景”入口生成版本 5、米制场景，正常 IPC 保存/重新读取字节一致。SOURCE ZIP 含 1 个场景、77 个资源文件，没有遗漏项或资源警告；Viewer 包约 225 MB。实体 ID、层级、Transform、显隐/锁定、资产编号、实例参数和遥测绑定一致，15 处图片引用按部署规则重定位。
- 场景原静态阴影已过期，导出首先被正常保护拦截。在独立副本调用原有“更新阴影”后再导出，没有绕过签名校验，也没有覆盖原场景。临时脚本早期误用旧场景版本、缺少会话授权/共享图片上下文的失败不计入验收，最终采用正常加载、保存及绑定上下文。
- 独立 Viewer 和通用同源 iframe 均通过真实 Intel UHD 630 硬件 WebGL 检查，140 个模型运行实例、192 个合批实体就绪，模型待处理/失败均为 0，环境和天空盒为 ready。完整首帧蒙版结束后才检查；诊断面板出现不代表所有资源已经完成。报告包含逐帧 P95，关闭诊断后 `onAfterRender` 观察器从 4 回落到 2，场景继续渲染，漫游可以正常启停。此处 iframe 是本地通用宿主，不等同于真实中台大屏业务联调。
- 30 分钟合成持续输入与 20 次漫游启停通过，源场景未变。每次重进后的 Mesh 数为 3743，观察器数量相同，环境索引建立计数始终为 78。JS heap 从约 662 MB 在中段上升到 793 MB，最后约 10 分钟保持平台；没有声称内存完全不增长，也没有用该浸泡的 FPS 作为稳态收益。GPU 进程工作集不能当作显存值。
- 后续确认并修复隐藏内置动画仍求值的问题。真实动画目标的 20 次启停回归通过；额外自包含 GLB（1 个 skin/skeleton、Idle/Walk/Run/Jump 四个片段）经真实加载器加载，暂停、恢复、第一/第三人称切换和卸载通过，卸载后 skeleton/AnimationGroup 均为 0。该补充不改变前述性能场景使用的无骨骼默认人物路径。
- 最新完整构建通过；Windows unpacked 产物生成到测试目录，不覆盖现有安装。打包版真实中台项目冷/暖打开均通过完整资源就绪，无错误，分别为 `83,998.9 ms` / `96,273.3 ms`。原版探索值为 `92,148 ms` / `92,665.7 ms`；各仅 1 个样本，且有普通启动与打包启动的形态差异，不能当作正式性能分位数或归因收益。冷打开降低 20%、重复打开降低 30% 的建议目标没有达成。
- 天空盒读取阶段本次观测为冷 `1018.8 → 708.9 ms`、暖 `943.3 → 758.1 ms`，与隔离字节流实验的方向一致；全量打开仍由脚本初始化、资源准备、GPU 上传及 GC 等共同决定。这是保留有界字节流改动的局部证据，不是整体打开速度承诺。
- 未执行 NSIS 安装升级、真实中台大屏宿主联调或任何线上发布。真实性能场景为当前工厂场景，不能推广为所有项目、全部设备故障轨迹和任意硬件的验收结果。
