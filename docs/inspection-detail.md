# 设备零件爆炸图与大屏联动

现在由**数据中台大屏按钮配置爆炸图**：场景点击设备后传递设备类型，大屏按类型选择模型管理中的固定高模版本，独立 Babylon Viewer 加载该版高模及数据库中的零件规则。场景继续使用低模，新流程无需在场景中填写高模或零件 JSON。

带操作截图、可下载 meta 示例和故障排查的教程见[设备零件爆炸图操作教程](inspection-guide.html)。

## 配置顺序

### 1. 在中台模型管理分别登记低模和高模

同一类设备登记两条模型记录，使用不同的模型编号，例如 `CONVEYOR-LOW-01` 和 `CONVEYOR-HIGH-01`：

| 内容 | 场景低模 | 爆炸图高模 |
| --- | --- | --- |
| 模型用途 | 场景低模（`SCENE`） | 爆炸图高模（`INSPECTION`） |
| 设备类型 | 实际平台类型编码，例如 `conveyor` | 与低模一致的编码 |
| 模型文件 | 原有低模资源 | 自包含 GLB/glTF，保留可独立移动的分件节点 |
| 完整 meta | 按原模型需要维护 | 在“版本元数据”上传或编辑完整 JSON，必须包含 `inspection.parts` |
| 使用位置 | 编辑器场景 | 大屏按钮按类型引用固定版本 |

“模型类型”描述资源类型，例如 `glb`；“设备类型”是中台设备类型字典的 `devType` 编码。两者不能互换，也不能用中文显示名称替代编码。类型匹配区分大小写。旧记录缺省为 `SCENE`。

高模编辑弹窗的“元数据维护方式”提供“保留现有”“上传 JSON”“编辑 JSON”。上传后可以继续编辑；点击“校验元数据”确认规则，再保存。只改 meta、模型用途或高模设备类型，也会生成新版本；原来固定的旧版本不会自动变化。历史版本详情读取该版完整 meta 和文件，不拼接当前版本的 meta。

旧模型如果只有 `meta.json` 文件链接、尚未把 JSON 入库，须在编辑弹窗显式上传或粘贴完整 JSON 后保存新版本。查看旧记录不会自动读文件回填数据库。

### 2. 在数字孪生编辑器使用场景低模

1. 打开已绑定数据中台的工程，同步普通模型库。普通列表读取 `SCENE` 用途；爆炸图高模无需拖入主场景。
2. 使用低模建立场景设备，为实例填写真实且可精确定位的资产编号 `assetCode`。
3. 使用新版编辑器同步模型并保存场景，使中台设备类型编码进入模型资源及实例。旧场景没有类型时，需要同步并重新保存发布，不能由中文名称推断类型。
4. 用新版编辑器重新发布数字孪生，再在中台大屏中绑定该发布。只升级中台而继续使用旧 Viewer，无法获得新设备上下文与高模加载能力。

默认设备点击、仅高亮和显式聚焦均可提供设备上下文；配置为 `ignore` 的点击仍保持忽略。新流程不要求在“高精度详情”中准备高模，不要求“打开设备详情”点击效果，也不要求开启“展示图表”。若需点击设备时打开绑定子大屏，仍按已有“展示图表”流程配置。

### 3. 在大屏按钮添加“爆炸图”事件

1. 将主大屏 A 与按钮大屏 B 关联到同一个中台项目。在 A 中配置数字孪生 Runtime，来源选择该项目的当前发布或历史发布；详情入口与 Viewer 位于同一发布目录。B 可以完全没有 Runtime 组件。
2. 在 B 中添加普通按钮，或选中按钮组中的子按钮；将“点击动作”设为“爆炸图”。
3. 在“项目中的目标 Runtime”中选择当前项目的“主大屏 A / Runtime 名称”。列表读取项目关联的大屏，不局限于 B 的组件；当前正在编辑的屏使用未保存的组件配置。手填 URL 的旧 Runtime 没有明确项目归属，不进入项目候选列表。
4. 点击“添加设备类型映射”，依次选择“设备类型”“爆炸图高模”“固定版本”。模型候选只显示该类型的高模；可输入模型名称搜索。每种类型保留一条映射。
5. 保存并发布大屏。缺失高模版本、重复类型等错误需要先修正；服务端还校验 Runtime 的项目和大屏归属、目标组件及高模固定版本。
6. 从主大屏 A 启动展示，将 B 作为主屏中的引用内容页或设备点击打开的浮层展示。先在 A 的 Runtime 中选中设备，再点击 B 中的按钮。设备打开的子屏会核对来源会话与当前选择，不能把设备上下文发到另一个 Runtime。

目标绑定保存在 `data.digitalTwinRuntimeTarget={projectId,screenId,widgetId}`，三个身份同时匹配；普通按钮和按钮组子项格式一致，前两项是字符串 Long。不同大屏的组件 ID 可以相同，因此不能只凭 `widgetId` 跨大屏匹配。旧 `digitalTwinRuntimeWidgetId` 继续按本屏或打开子屏的来源场景解析。

高模映射另存为 `deviceType → modelId + versionId`，不保存运行时设备身份、文件 URL 或完整 meta。版本号 `V1` 仅供显示，实际引用是字符串 `versionId`。上传高模 V2 后，原按钮仍使用 V1；切换版本需要明确修改映射并重新发布大屏。

**配置范围与运行范围：**项目目录可用于跨大屏选择目标，执行时使用当前展示宿主中已加载并完成握手的实例。单独打开 B、在其他浏览器标签页打开 A，或只引用了 A 的普通组件，都不会取得 A 的 Runtime 与设备选择。此时会提示目标未加载；请从承载目标 Runtime 的主屏入口展示 B。此能力不新增独立窗口通信，也不接通无中台宿主的 Viewer 内嵌大屏协议。

### 4. 运行时查看

先点击场景中的设备，再点击“爆炸图”按钮。大屏按当前设备类型读取已配置的固定版本，加载成功后自动展开至 100%。详情提供零件树、0–100% 展开程度、复原、聚焦、隔离和关闭。

选择零件会更新大屏的设备及 `partKey` 上下文；展开、相机和隔离属于查看状态，不写回场景，也不作为业务查询参数。切换设备、重载场景或取消选择会使旧详情及其迟到结果失效。关闭详情会清除零件上下文，仍有效的设备上下文保留。

单独重载详情页面时，系统清除旧 `partKey`，重新协商能力并加载当前仍有效的固定版本，加载成功后恢复至 100% 展开。旧会话的迟到成功或失败不会覆盖新页面；同设备、同参数的聚焦回执也不会中断正在进行的高模加载。

无设备选择、缺少设备类型、没有类型映射、版本不可用或参数不适用时会提示原因；不会随意选第一个高模，也不会回退最新版本。

## 高模 meta 示例与制作要求

高模必须具有实际零件/装配节点。整体单网格不能自动恢复内部零件；增加面数或贴图清晰度不能补齐结构。GLB/glTF 的缓冲区和纹理必须内嵌，外部 `.bin`、图片或 URL 会被拒绝。

以下示例中的节点路径必须改为真实模型路径，其他已有 meta 字段应一并保留。完整 JSON 存入数据库，并生成同内容的 meta 文件以保持旧资源消费兼容。

```json
{
  "lengthUnit": "meter",
  "inspection": {
    "schemaVersion": 1,
    "parts": [
      {
        "partKey": "assembly.base",
        "name": "底座",
        "nodePath": "AssemblyRoot/Base",
        "axis": { "x": 0, "y": 1, "z": 0 },
        "distanceMeters": 0,
        "fixed": true
      },
      {
        "partKey": "drive.motor",
        "name": "电机",
        "nodePath": "AssemblyRoot/Motor",
        "axis": { "x": 1, "y": 0, "z": 0 },
        "distanceMeters": 0.5,
        "fixed": false
      }
    ]
  }
}
```

- `lengthUnit` 位于 meta 顶层，支持 `meter/m`、`centimeter/cm`、`millimeter/mm`；普通模型缺省为米。`distanceMeters` 始终是米，不随源文件单位变化。
- `partKey` 是稳定业务装配位标识，`nodePath` 是当前版本的节点定位路径；两者各自在清单内唯一。路径 `.` 表示加载根，其余路径不包含加载根，按 `/` 逐级连接，同级节点名称须唯一。不允许空段、`.`/`..` 段、逗号、分号和换行。
- `axis` 是有限非零的世界方向，`distanceMeters` 非负，`fixed` 为布尔值。清单数量为 1–10000；总消息预算超限会报错，不截断。
- 可选 `parentPartKey` 必须指向已有零件且不能循环；它不会改变模型的真实节点层级。实际可移动祖先控制整条分支，后代不重复叠加；固定祖先下的后代保持固定。可移动祖先与固定后代冲突会被拒绝。
- 可选 `inspection.configuration` 形如 `{ "id": "CV-6m", "parameters": { "width": 6 } }`。提供时必须与低模当前**完整参数快照**一致；参数缺失、超预算或不一致会阻止加载。省略时按设备类型使用，维护者仍须确认尺寸、零件数等适用性。当前每个类型只有一条映射，不按参数自动挑选多个版本。
- 高模首期展示静态装配，不执行低模参数脚本，不播放会修改零件姿态的动画。

## 零件数据与反向定位

为零件指标配置实际 HTTP 或流程 API 数据源。将“点击参数策略”设为“仅传递声明参数”，声明接口实际依赖的设备字段以及 `partKey`，并按需要开启“必填点击参数”。例如仅按资产与装配位查询，就声明 `assetCode`、`partKey`；只有接口确实依赖时才声明 `namespace`、`deviceType`、`deviceNo`。

`namespace` 和 `deviceNo` 是可选的真实业务身份，不会从 `assetCode` 伪造。按类型打开高模不要求这两项；数据源若声明为必填而未提供，则不请求并清除旧结果。`0` 和 `false` 有效，空白、`null` 和缺失无效。HTTP Body/流程参数映射发生在声明过滤之后，不能补回已过滤的字段。设备级数据源只声明自身依赖，避免切换零件时重复刷新。流程结果集读取既有快照，不会因为传入参数就自动过滤或重跑。

普通表格、状态表格或任务明细表可开启“记录定位设备零件”，配置目标 Runtime、设备资产编号字段和零件标识字段，例如 `device.code`、`part.key`。字段读取原始记录，支持点号路径，值须为非空字符串。

**新大屏配置流程的反向定位边界：**当前设备已通过爆炸图按钮打开高模时，表格可复用详情定位该设备零件；跨设备记录需要先选择目标设备并通过爆炸图按钮打开其固定版本，再定位零件。系统不会猜测其他按钮的映射。旧场景的显式高模绑定仍保留原来的跨设备打开路径。

## 版本、发布与兼容边界

- 新按钮配置由大屏持久化；后端保存、发布及同库克隆校验固定版本，并保护草稿、保留发布快照及冻结子屏引用的模型不被删除。
- 项目 Runtime 目标按实际项目关系和组件配置校验，不信任大屏 JSON 自报的项目归属。新建可用顶层 `projectId` 原子关联项目，集成更新接口同步按目标项目校验；已有目标的源屏换项目或解除关联前须先清除旧目标，被其他大屏引用为目标 Runtime 的大屏同样不能直接删除、移除或降级对应组件或解除项目归属，项目差量保存也执行相同保护。同项目复制或克隆保留明确目标，实际跨项目克隆带目标的源屏时拒绝执行；未参与克隆的外部引用屏按自身项目校验并保留原样。旧本屏组件引用的复制逻辑保持兼容。
- 高模文件和数据库 meta 按固定版本读取，需要访问当前中台受控文件接口。**新按钮流程需要中台在线，不会自动将高模塞进场景离线包。**
- 旧 `InspectionBinding` 及场景内高模资源仍兼容，其完整资源包摘要与发布规则继续生效；旧包摘要与平台单文件摘要不能混用。新流程不伪造旧本地资源路径或包摘要。
- 基础 v1 点击协议保持兼容，扩展能力独立协商。新版中台和新版 Viewer 需配套；旧发布必须重新发布后生效。
- 项目旧 JSON 转移及完整归档，目前均不支持大屏固定高模版本及残留项目 Runtime 目标的跨库重映射；迁入/迁出会提前明确拒绝。普通模型归档保留其各版本用途、类型和 meta，不等于已支持大屏映射迁移。
- 详情没有内置业务指标区。零件指标、告警或维修数据放在大屏已有组件中，通过数据源联动。
- 实际单位、节点结构、适用配置、业务字段和目标硬件性能仍须以真实模型验收；隔离样例不能替代实际业务证据。
