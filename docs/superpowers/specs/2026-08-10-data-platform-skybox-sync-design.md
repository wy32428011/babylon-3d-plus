# 数据中台天空盒资源与数字孪生编辑器同步设计

- 日期：2026-08-10
- 状态：已完成需求访谈，待用户复核书面规范
- 影响仓库：`CentralDataPlatform`、`babylon-3d-plus`
- 设计结论：新增独立天空盒领域模块，并在编辑器中新增独立的增量、原子、后台同步管线

## 1. 背景

数据中台当前在“模型”菜单分组下提供模型管理、环境模型和组合模型，但没有独立的天空盒资源管理能力。数字孪生编辑器已经具备项目本地 HDR/EXR 天空盒导入、资源卡片、场景应用、参数调整、保存和发布能力，但打开数据中台项目时不会同步数据中台天空盒。

本设计建立一套全局共享的天空盒资源库，并使编辑器在打开数据中台项目时把资源安全同步到共享缓存。项目本地天空盒与数据中台天空盒必须并存，远端更新必须能够刷新既有场景，远端删除不得破坏历史场景。

## 2. 目标

1. 在数据中台“模型”子菜单中增加“天空盒”。
2. 支持天空盒分页列表、名称搜索、上传、改名、替换文件和删除。
3. 仅接受 HDR/EXR，单文件上限为 512 MiB，并执行内容级校验。
4. 天空盒作为全局共享资源，不建立项目绑定关系。
5. 打开数据中台项目时在后台自动同步天空盒，不阻塞项目和场景打开。
6. 通过稳定资源 ID、revision 和 SHA-256 实现增量同步。
7. 同步采用整批原子提交；失败时旧资源库保持不变。
8. 项目本地天空盒和数据中台天空盒在编辑器中同时可用并明确标识来源。
9. 数据中台替换文件后，既有场景自动使用最新资源并保留场景级显示参数。
10. 数据中台删除资源后，从新选择列表隐藏，但保留兼容缓存，避免破坏历史场景。
11. 发布时只打包场景实际引用的天空盒，使 Viewer 可离线运行。

## 3. 非目标

本期不实现：

- 天空盒与项目的绑定关系；
- 天空盒版本历史、版本选择或回滚界面；
- `.env` 天空盒支持；
- HDR/EXR 在线预览或自动缩略图生成；
- 可选 PNG/JPG 缩略图；
- 批量导入、批量导出和批量删除；
- 定时轮询同步；
- 自动清理孤立兼容缓存；
- 数据中台鉴权模式变更；
- 对现有模型、环境模型、组合模型或图片同步进行无关重构。

## 4. 已确认决策

| 主题 | 结论 |
|---|---|
| 资源范围 | 全局共享，不绑定项目 |
| 文件格式 | 仅 `.hdr`、`.exr` |
| 单文件上限 | 512 MiB |
| 管理能力 | 列表、搜索、上传、改名、替换、删除 |
| 同步时机 | 数据中台项目自动同步；本地项目仅手动同步 |
| 同步方式 | 后台、增量下载、整批原子提交 |
| 缓存身份 | 稳定资源 ID + revision + SHA-256 |
| 本地资源 | 与数据中台资源分源并存 |
| 手动操作 | 天空盒 Tab 提供同步和失败重试 |
| 重复策略 | 名称不区分大小写唯一，SHA-256 全局去重 |
| 远端替换 | 场景自动跟随最新文件并保留显示参数 |
| 远端删除 | 卡片隐藏，兼容缓存保留，不允许新选择 |
| 缩略图 | 本期不生成，使用格式和天空盒图标 |
| 发布 | 只打包场景实际引用文件 |
| 架构 | 独立后端模块 + 独立编辑器同步管线 |

## 5. 用户体验设计

### 5.1 数据中台菜单

菜单顺序保持现有结构并追加天空盒：

```text
模型
├─ 模型管理
├─ 环境模型
├─ 组合模型
└─ 天空盒
```

新增页面路由 `/skyboxes`，沿用现有资源页的 `Card + AppTable` 风格。

### 5.2 天空盒列表

列表支持名称搜索和分页，默认按更新时间倒序。

| 列 | 内容 |
|---|---|
| 天空盒名称 | 全局唯一业务名称 |
| 格式 | `HDR` 或 `EXR` 标签 |
| 原文件名 | 上传文件的安全文件名 |
| 文件大小 | 格式化为 MiB |
| SHA-256 | 显示缩略值，Tooltip 展示完整值 |
| 更新时间 | 最近一次元数据或文件更新 |
| 操作 | 修改名称、替换文件、删除 |

本期不展示真实缩略图，不提供项目关联数量和项目配置入口。

### 5.3 上传

1. 用户点击“上传天空盒”。
2. 一次选择一个 `.hdr` 或 `.exr` 文件。
3. 前端以去除扩展名后的文件名回填天空盒名称。
4. 用户可以在提交前修改名称。
5. 前端先校验扩展名、空文件和 512 MiB 上限。
6. 后端执行最终校验，包括名称唯一、哈希去重、文件内容、分辨率和大小。
7. 创建成功后关闭弹窗并刷新第一页。

修改名称和替换文件使用两个独立操作。替换文件不会自动改变业务名称。

### 5.4 编辑器天空盒 Tab

保留现有天空盒 Tab，不增加第二套面板。

- 同时展示“项目本地”和“数据中台”资源。
- 卡片增加来源标识。
- 同名资源分别展示，不按名称覆盖。
- 搜索匹配业务名称、原文件名和来源。
- 继续使用现有天空盒图形和 HDR/EXR 格式标识。
- 顶部提供“从数据中台同步”按钮。
- 同步中显示阶段、完成数和总数。
- 失败时显示错误和“重试”。
- 当前天空盒已从数据中台删除时显示下线警告，但不清空场景效果。

## 6. 数据中台后端设计

### 6.1 模块边界

新增 `twin-module-skybox`，只负责：

- 天空盒元数据；
- HDR/EXR 上传和替换；
- 文件安全校验；
- SHA-256 与 revision；
- 存储文件生命周期；
- 管理端和编辑器共用的查询接口。

模块依赖现有 common core、web、mybatis 和 storage 能力，不依赖项目关系模块，不复用环境模型表。

### 6.2 数据表

新增 `dt_skybox`：

```sql
CREATE TABLE dt_skybox (
    id BIGINT PRIMARY KEY,
    skybox_name VARCHAR(128) NOT NULL,
    file_name VARCHAR(255) NOT NULL,
    storage_path VARCHAR(512) NOT NULL,
    file_url VARCHAR(512) NOT NULL,
    file_format VARCHAR(16) NOT NULL,
    file_size BIGINT NOT NULL,
    file_sha256 CHAR(64) NOT NULL,
    revision BIGINT NOT NULL DEFAULT 1,
    created_at DATETIME(6) NOT NULL,
    updated_at DATETIME(6) NOT NULL,
    UNIQUE KEY uk_dt_skybox_name (skybox_name),
    UNIQUE KEY uk_dt_skybox_sha256 (file_sha256),
    KEY idx_dt_skybox_updated_at (updated_at)
);
```

迁移应显式使用与当前数据库兼容的不区分大小写字符集/排序规则，使名称唯一约束不区分大小写。最终迁移版本号以实施时仓库中的最新 Flyway 版本为准，不在设计文档中预占固定编号。

约束和语义：

- `id` 是跨修改稳定的资源身份。
- `storage_path` 仅供后端删除和读取，不向前端公开。
- `file_format` 仅允许 `HDR`、`EXR`。
- `file_size` 必须大于 0 且不超过 512 MiB。
- `file_sha256` 保存 64 位小写十六进制摘要。
- 名称改动或文件替换后 `revision` 加一。
- 替换为当前记录完全相同的文件可作为无变化请求返回，不创建新存储文件、不增加 revision。
- 不增加项目关系表、版本表或软删除字段。

### 6.3 API

保持现有 POST-only 约定：

| 接口 | 请求 | 说明 |
|---|---|---|
| `POST /api/v1/skyboxes/query` | JSON | 分页查询，管理端与编辑器同步共用 |
| `POST /api/v1/skyboxes/detail` | JSON `{ id }` | 查询详情 |
| `POST /api/v1/skyboxes/create` | multipart | `skyboxName`、`skyboxFile` |
| `POST /api/v1/skyboxes/update-name` | JSON | `id`、`revision`、`skyboxName` |
| `POST /api/v1/skyboxes/replace-file` | multipart | `id`、`revision`、`skyboxFile` |
| `POST /api/v1/skyboxes/delete` | JSON | `id`、`revision` |

查询响应公开字段：

```json
{
  "id": "123",
  "skyboxName": "晴朗草原",
  "fileName": "sunny-meadow.hdr",
  "fileUrl": "/api/v1/files/...",
  "fileFormat": "HDR",
  "fileSize": 134217728,
  "fileSha256": "64-character-lowercase-sha256",
  "revision": 3,
  "createdAt": "2026-08-10T10:00:00",
  "updatedAt": "2026-08-10T11:00:00"
}
```

`BIGINT` ID 继续以字符串返回，避免 JavaScript 精度损失。查询最大页大小遵循现有资源接口上限，编辑器通过有界分页拉取全部资源。

### 6.4 上传与替换事务

上传使用流式存储和补偿式事务：

1. 规范化并校验名称、扩展名和声明大小。
2. 通过 `StorageService` 流式写入文件，同时计算 SHA-256。
3. 从存储重新打开文件流，执行 HDR/EXR 内容校验。
4. 校验名称和 SHA-256 唯一性。
5. 插入或更新数据库记录。
6. 任一步失败时删除本次新建的存储文件。
7. 替换成功并提交数据库后再删除旧文件。
8. 旧文件删除失败不把已成功的新版本误报为失败；记录包含资源 ID 和存储对象标识的错误日志，供后续回收。

更新名称、替换文件和删除均携带 `revision`。数据库更新使用乐观锁，冲突时返回“资源已更新，请刷新后重试”，不得静默覆盖。

### 6.5 文件校验

数据中台和编辑器使用等价规则：

- 只接受 `.hdr`、`.exr`；
- 文件非空；
- 单文件最大 512 MiB；
- HDR 必须是 Radiance RGBE 全景格式；
- HDR 朝向必须为 `-Y height +X width`；
- HDR 宽度范围为 8–32767；
- HDR 校验像素数据或 RLE 扫描线完整性；
- EXR 校验 Magic Number、属性结构和 `dataWindow`；
- 最大像素数为 `32 × 1024 × 1024`；
- 不信任客户端 MIME；
- 文件名清除路径分隔符、控制字符和 Windows 保留名风险；
- 通用文件白名单补充 `.exr`，但天空盒接口仍执行专用内容校验。

## 7. 编辑器同步设计

### 7.1 独立管线

新增独立天空盒同步服务及 IPC，包含：

- `syncDataPlatformSkyboxes`；
- `retryDataPlatformSkyboxSync`；
- `onDataPlatformSkyboxSyncProgress`；
- 最近进度读取；
- 应用退出时取消和等待。

进度阶段：

```text
querying → downloading → validating → promoting → completed
                                                  ↘ failed
```

天空盒同步与模型、图片同步互不影响。已有天空盒任务运行时，重复触发复用当前任务，不创建并发覆盖任务。

### 7.2 自动触发

自动同步入口：

- 从数据中台项目列表打开；
- 数据中台深链；
- 重新打开带有效数据中台绑定的最近项目。

普通本地项目、普通本地场景和空白编辑器不自动联网。用户可在天空盒 Tab 手动同步。手动同步写入统一共享资源根，不把普通本地项目改造成数据中台绑定项目。

### 7.3 缓存布局

```text
SharedResources/
├─ Assets/
│  └─ Skyboxes/
│     └─ DataPlatform/
│        ├─ Skybox-123/
│        │  └─ skybox.hdr
│        └─ Skybox-456/
│           └─ skybox.exr
└─ .babylon-editor/
   └─ data-platform-skybox-index.json
```

- 包目录只包含稳定 ID，不包含业务名称。
- 名称变化不改变本地路径。
- 同格式替换覆盖稳定文件路径，并通过 `assetRevision` 触发纹理重载。
- HDR/EXR 格式互换时生成新扩展名文件；旧扩展名文件保留为历史场景兼容文件。
- 场景不保存远程 URL，只保存授权后的本地路径和本地资源 URL。

### 7.4 同步清单

清单版本初始为 1，记录：

- 资源 ID；
- 业务名称；
- revision；
- SHA-256；
- 格式；
- 文件大小；
- 当前相对路径；
- `active` 或 `orphaned` 状态；
- 最近同步时间。

远端删除的记录从 `active` 转为 `orphaned`。孤立记录不进入新选择列表，但文件和元数据保留，使旧场景继续加载并能显示明确警告。

### 7.5 增量计划

1. 有界分页查询完整远端清单。
2. 校验响应结构、资源 ID、名称、格式、revision、大小和 SHA-256。
3. 拒绝重复 ID、重复名称和重复 SHA-256。
4. 读取本地同步清单。
5. 按 ID 对比：
   - SHA-256、格式和大小一致：文件不下载；名称或 revision 变化只更新元数据。
   - SHA-256 或格式变化：下载并校验。
   - 新 ID：下载并校验。
   - 远端缺失 ID：标记为 `orphaned`。
6. 生成下一版清单。
7. 所有变化文件成功后整批原子提交。

限制：

- 单文件 512 MiB；
- 单次累计下载 8 GiB；
- 下载并发 2；
- 查询页数和总记录数有安全上限；
- 请求和单文件下载均设置超时；
- 下载期间流式计算 SHA-256，必须匹配服务端摘要。

### 7.6 原子提交与回滚

变化文件先进入任务专属暂存目录。提交阶段维护明确的 promotion state：

- 新文件目标；
- 已存在目标备份；
- 新文件是否已推广；
- 清单是否已替换。

任一提交步骤失败时按反向顺序恢复。完整失败不会更新可见资源清单，也不会删除旧有效文件。回滚不完整时抛出专用错误，保留恢复目录并输出准确位置；不得静默吞错。

任务成功、取消或可安全失败后，只清理由本任务创建且已验证位于共享资源根内的暂存目录。

### 7.7 资源合并

项目资源读取逻辑调整为：

1. 扫描当前项目本地 `Assets/Skyboxes`；
2. 从共享同步清单读取 `active` 数据中台资源；
3. 合并两类资源；
4. 本地资源按路径保持独立；
5. 数据中台资源按稳定 ID 去重；
6. 同名资源不互相覆盖；
7. 排序按名称、本地优先、稳定 ID。

资源卡片增加来源、数据中台 ID、revision 和 SHA-256 元数据。`orphaned` 资源只用于兼容判断，不生成可选卡片。

## 8. 场景引用与运行时

### 8.1 可选来源字段

天空盒场景配置增加：

```ts
dataPlatformResourceId?: string;
```

该字段必须是可选字段，不提高场景文件主版本号。

### 8.2 重关联顺序

1. 若存在 `dataPlatformResourceId`，优先按稳定 ID 匹配共享资源；
2. 否则按精确路径或本地资源 URL 匹配；
3. 最后按“包目录名 + 主文件名”执行旧场景兼容匹配；
4. 多个候选时拒绝猜测。

### 8.3 远端替换

同步完成后，若当前场景引用的资源发生变化：

- 更新 `sourcePath`、`sourceUrl`、格式和 `assetRevision`；
- 保留 rotation、intensity、resolution 和天空盒实体 Transform；
- 通过现有命令系统提交，产生可撤销记录并标记场景未保存；
- 同格式替换通过稳定路径和新 `assetRevision` 强制 Babylon.js 重新加载；
- 名称变化只刷新资源卡片，不重载纹理、不改写场景实体名称。

### 8.4 远端删除

- 从资源选择列表隐藏；
- 保留兼容文件和孤立清单记录；
- 当前场景继续运行；
- UI 显示“资源已从数据中台删除”的警告；
- 不允许新场景重新选择该资源；
- 本期不自动清理孤立文件。

## 9. 发布与导出

现有发布链路继续按场景引用收集天空盒：

1. 只收集场景实际引用的 HDR/EXR；
2. 预检本地文件存在、格式一致且可读取；
3. 把文件复制到发布包；
4. 将场景资源 URL 重写为发布包相对 URL；
5. Viewer 不连接数据中台；
6. `dataPlatformResourceId` 可作为来源元数据保留，但运行时不依赖。

孤立资源仍有兼容缓存时允许发布，并显示警告。缓存缺失时发布预检失败，错误必须包含资源名称、ID 和缺失资源上下文，不生成残缺包。

## 10. 安全与性能

### 10.1 下载安全

- 仅允许 HTTP/HTTPS；
- 相对 URL 基于配置的 Base URL 解析；
- 拒绝 URL 内嵌凭据和危险协议；
- 默认拒绝下载重定向；
- 校验预期来源、超时、单文件大小和累计大小；
- 文件不整体载入内存；
- 所有写入路径必须位于受控共享资源根；
- 不跟随符号链接；
- 拒绝目录穿越；
- 日志不泄露凭据、完整远程 URL或无必要的内部存储根。

### 10.2 上传安全

- 使用流式存储，禁止 `MultipartFile#getBytes()` 读取大型文件；
- 服务端内容校验是最终可信边界；
- 数据库唯一索引处理并发创建竞态；
- 存储和数据库跨边界失败执行补偿清理；
- 错误日志包含资源 ID、名称和阶段，避免只有通用“上传失败”。

### 10.3 资源边界

- 单文件 512 MiB；
- 同步累计下载 8 GiB；
- 下载并发 2；
- 无定时轮询；
- 无界缓存、无界分页、无界并发均禁止；
- 孤立兼容缓存的自动清理明确留待后续独立需求。

## 11. 故障语义

| 故障 | 结果 |
|---|---|
| 查询失败 | 保留旧资源库，显示重试 |
| 下载超时 | 整批失败，旧库不变 |
| 哈希不匹配 | 拒绝提交 |
| HDR/EXR 损坏 | 拒绝提交 |
| 磁盘空间不足 | 不替换旧资源 |
| 原子提交失败 | 反向回滚 |
| 回滚不完整 | 保留恢复目录并明确报错 |
| 远端删除 | 卡片隐藏，兼容缓存保留 |
| 应用退出 | 取消任务并等待资源释放 |
| 重复触发 | 复用当前任务 |
| 乐观锁冲突 | 提示刷新后重试，不覆盖他人修改 |

## 15. 验收标准

1. 数据中台“模型 → 天空盒”能够查询、上传、改名、替换和删除。
2. 前后端仅接受有效 HDR/EXR，执行 512 MiB 和内容级限制。
3. 重复名称和重复文件不能创建。
4. 打开数据中台项目不被天空盒同步阻塞。
5. 未变化资源不重复下载。
6. 任意同步失败不破坏旧资源库。
7. 项目本地和数据中台天空盒并存且来源清晰。
8. 远端替换后场景自动升级并保留显示参数。
9. 远端删除不破坏已有场景，也不能被新场景选择。
10. 发布包只包含实际引用天空盒并可离线运行。
11. 不遗留任务进程、文件句柄、暂存目录或调试代码。
12. 不覆盖两个仓库中的用户已有改动。
