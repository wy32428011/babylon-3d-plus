# 堆垛机运动箭头

更新时间：2026-09-23。

堆垛机的数据驱动属性提供“运动箭头”，分别显示行走、升降、前叉和后叉的运动方向。四路共用箭头样式和外观参数，每路可以独立开关、选择挂点和反转方向。行走箭头自动覆盖固定轨道全长，升降箭头在载货台当前高度留出随平台移动的缺口；其余通道可按部件校准覆盖范围。默认关闭；旧场景没有新配置时保持现有外观，启用总开关后四路默认开启。

## 配置和预览

1. 选中 `deviceType=stacker` 的模型，在“数据驱动”中确认设备绑定，再勾选“启用运动箭头”。默认使用青蓝色“移动双箭头”，呼吸效果默认关闭。
2. 从特效库拖入箭头到“箭头样式”框，或通过下拉列表选择。支持十种内置样式：输送方向箭头、移动双箭头、管线流动箭头、流动箭头，以及单一直线箭头、连续箭头流向、分段式箭头、宽幅带式箭头、双列前进箭头、高速流动箭头。拖入只改变当前堆垛机四路共用的样式，不创建新实体，也不覆盖颜色、尺寸、挂点或设备绑定；其它特效、模型和外部文件不会被接受。
3. 展开“共用外观与动画”，可调整颜色、发光强度、透明度、箭头尺寸、间距、流动速度及呼吸参数。“发光强度”范围为 `0–10`，默认 `1`，独立于透明度和启用状态；旧配置没有该字段时使用默认强度，保存的 `0` 保持为 `0`。前四种样式的流动速度使用视觉米/秒，后六种为视觉倍率；两者都不表示模型或现场设备的真实速度。速度设为 `0` 时箭头停止流动，仍按设备运动状态显示或隐藏；呼吸可以单独启用。
4. 按需关闭“启用行走箭头”“启用升降箭头”“启用前叉箭头”或“启用后叉箭头”。每路展开“挂点与范围”后，可以指定部件、显示面、离面距离、宽度、横向偏移，以及“反转箭头方向”。行走的长度和沿运动偏移由固定轨道自动决定，输入框不可编辑；升降和双叉仍可调整长度及沿运动偏移。反转只校准显示，不改变堆垛机驱动。
5. 各路使用“正向”“反向”“停止”检查效果，“结束预览”关闭该路预览。四路可同时预览，预览只显示箭头，不移动模型。切换模型、场景或运行模式，关闭总开关或对应通道后，临时预览结束。

## 四路放置与挂点校准

| 通道 | 自动挂点及显示方式 | 跟随关系 |
| --- | --- | --- |
| 行走 | 优先模型声明的固定轨道，按固定轨道全长显示，默认顶面，可切换侧面 | 固定在轨道上，不随底盘平移；整体移动、旋转或缩放场景模型时随轨道变化 |
| 升降 | 从运动部件声明与立柱节点名称识别立柱，固定竖直面，扣除载货台当前高度区间 | 随立柱水平移动，箭头沿升降轴流动；缺口随载货台升降 |
| 前叉 | 优先模型声明的前叉第二级节点，其次第一级节点 | 随载货台升降及前叉伸缩 |
| 后叉 | 优先模型声明的后叉第二级节点，其次第一级节点 | 随载货台升降及后叉伸缩 |

行走优先使用模型声明的固定轨道（`fixedNodes`），合并下轨各段的完整范围；同时声明上下轨或声明轨道父容器时，使用下轨几何。没有有效声明时，按轨道节点名称识别，或在“行走部件”中指定固定轨道节点校准。已识别声明轨道时，旧底盘挂点、局部轨道挂点或失效的旧挂点不会截短或阻断整轨显示。无法识别固定轨道、立柱、载货台或独立货叉时，对应箭头隐藏并显示诊断，不会用整机包围盒猜测挂点。只有一组货叉的模型不会自动把同一挂点同时用于前叉和后叉；应根据模型结构关闭不适用的通道，或明确配置独立挂点。

在“行走部件”“升降部件”“前叉部件”“后叉部件”中填写唯一节点名、完整节点路径或唯一尾部路径，按 Enter 或移开焦点应用。需要使用该挂点且节点不存在、路径不唯一、部件无可测量几何、变换退化，或所选表面与运动方向垂直时，面板给出原因并隐藏该路箭头；行走已有有效声明轨道时忽略旧挂点。行走应选择固定轨道；升降选择立柱；前后叉分别选择实际伸缩的对应货叉，避免挂到不随货叉运动的外壳。

行走箭头始终使用固定轨道的完整长度和纵向中心。旧场景中已经保存的短长度或沿运动偏移会继续保留，运行时自动改为覆盖整轨，不需要逐台清零；这两项在行走通道中不可编辑，宽度、横向偏移和离面距离仍可校准。

升降箭头覆盖立柱有效几何范围，并从中扣除载货台当前占据的高度区间，形成上下两段可见区域。载货台升降时缺口同步移动，平台所在高度不会继续绘制箭头；无法识别载货台时，该路隐藏并给出诊断。

除行走长度外，长宽为 `0` 时按对应部件范围自动适配；货叉箭头限制在货叉附近。手动尺寸使用模型局部米，跟随场景中的模型整体缩放；导入单位倍率和 GLB 部件自身的建模缩放不会重复放大尺寸。“沿运动偏移”沿本路运动轴调整，“横向偏移”沿箭头面的横向调整，“离面距离”用于避开表面闪烁。升降始终使用竖直面；其它三路可在顶面与侧面之间选择。箭头保留正常深度遮挡，货物或前方货架可以遮住箭头，需要时调整到外侧。

## 运动状态与异常

箭头沿用当前堆垛机的 `sourceId + deviceType + assetCode`，不新增 MQTT 订阅，也不需要再次配置方向点位。方向来自本帧堆垛机驱动实际执行的行走、升降和两路货叉位移。首帧吸附、基准校正与行程约束产生的位置纠偏不会作为正常运动箭头显示。

这里的“实际执行”指三维模型运行时的插值和动作执行结果，不等于 PLC 连续位置测量。视觉流速独立于驱动采样到的运动速度；开启箭头不会改变现有取放货、目标库位、行程和货叉联锁。

| 状态 | 箭头表现 |
| --- | --- |
| 本帧对应部件有有效位移 | 显示对应方向，箭头尖端和流动同步反向 |
| 行走与升降同时运动 | 两路可同时显示 |
| 到位或正常停止 | 停止流动，并在约 `120 ms` 内淡出 |
| 驱动执行收叉补偿 | 对应货叉按本帧收回方向显示 |
| 未收到数据、绑定无效或冲突、数据过期 | 立即隐藏并显示诊断 |
| 故障或急停 | 立即隐藏，不保留淡出尾帧 |
| 本帧没有有效驱动结果 | 隐藏，避免沿用上一帧运动方向 |
| 模型隐藏、卸载或资源尚未就绪 | 隐藏；资源重新就绪后重新解析挂点 |

故障、急停和数据新鲜度沿用现有设备遥测归一化及绑定规则。数据恢复后，只有重新获得有效本帧运动结果才显示。每路卡片的“状态”用于排查方向、缺失挂点和隐藏原因，原“运行时诊断”继续提供设备身份、接收时间及标准化字段。

## 保存、复制与发布

配置保存在模型实例的 `telemetryBinding.stackerMotionArrows` 中，支持撤销重做、保存重开和复制后独立修改。临时预览、诊断文本及实时运动状态不进入场景、命令历史或发布配置。“恢复模型默认绑定”会移除堆垛机箭头配置并恢复默认关闭，该操作可撤销。

SOURCE 与 DIST 沿用场景中的配置，编辑器运行预览和发布 Viewer 使用同一套运动与绘制逻辑。没有配置的旧场景、已显式关闭的场景保持关闭。已有线上 Viewer 需要使用包含该功能的新版编辑器重新构建 Viewer 并重新发布；仅修改本地代码或保存场景不会更新旧发布包。

## 验证入口和证据范围

配置、会话、四路实际运动采样与编辑器命令：

```powershell
node scripts/telemetry-test.mjs stackerMotionArrowsConfig.test.ts stackerMotionArrowSession.test.ts stackerMotionState.test.ts
node --test tests/editor/stackerMotionArrows.integration.test.mjs
```

挂点几何、绘制生命周期与运行状态门控：

```powershell
node --test tests/runtime/stackerMotionArrowRenderer.test.mjs tests/runtime/stackerMotionArrowGap.test.mjs tests/runtime/stackerMotionArrowSystem.test.mjs
```

编辑器属性操作、四路预览、真实 WebGL 像素与本地遥测夹具：

```powershell
node scripts/smoke-stacker-motion-arrows.mjs
```

上述 smoke 生成 `output/stacker-motion-arrows/scene.scene.json`。完成构建后，可验证 SOURCE 与对应 DIST 的正常配置、显式关闭、旧场景和零值场景：

```powershell
npm run build
node node_modules/electron/cli.js tests/digitalTwin/stackerMotionArrowPackages.integration.mjs
node scripts/smoke-stacker-motion-arrow-viewer.mjs
```

截图、动画录制和验证产物保存在 `output/stacker-motion-arrows/`。上述命令是可复现的验证入口，执行结果以当前任务的实际测试记录为准。测试使用自包含堆垛机模型和本地 MQTT fixture，不能代替真实业务模型、现场 Broker、已安装编辑器或线上 Viewer 的验收。已有部署需重新发布后，使用项目实际连接与模型进行联调。
