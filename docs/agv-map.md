# AGV 产生器与地图数据接口

AGV 产生器位于 POI 库，复用设备产生器的模板实体、MQTT 动态生成、离线超时和产物点击绑定能力，并附加 AGV 地图显示。

## 坐标与显示

- 产生器实体的 `Transform.position` 是地图 `(0,0)`；旋转和实体缩放同样作用于地图。
- 地图是二维 XY 数据。默认地图 X → 场景 +X、地图 Y → 场景 +Z；两个轴均可映射到场景正/负 X、Y、Z，但不能使用同一个基础轴。
- 比例尺单位为“米/地图单位”，默认 `1`，允许范围 `0.001–1000`。修改后立即重建轨迹几何，不改变产生器位置。
- “地图轨迹展示”同时控制业务节点标记和运行路线。“整体地图底图”独立控制已上传 DXF 的完整线稿，隐藏底图不影响轨迹、节点和任务高亮。地图在编辑态和运行预览中都可显示，但不参与鼠标拾取。
- 地图选择包含两份内置示例和本产生器已导入的地图。

## 导入 NDC8 图纸

> 面向新图纸制作与第三方 DXF 改图的完整检查清单与报错排查，见 [AGV 地图 DXF 导入与修正规范](agv-dxf-import-spec.md)。

在桌面编辑器选中 AGV 产生器，点击「地图上传（DXF）」。编辑器将 DXF 原件复制到工程 `Assets/Cad/`，显示模型空间参考图，并把提取的地图保存到产生器。上传完成时，若产生器仍处于选中状态，视口会聚焦到整张图。重新上传会替换该产生器的底图及路网，撤销会同时还原两者。

- 底图保留受支持的线稿、NDC8 编号文字、图层颜色和点位填充。选择已导入的地图即可显示底图，轨迹开关独立控制运行路线及节点覆盖层。
- 转换从 `Ndc8_Point` 与 `Ndc8_PointID` 读取路网节点，从 `Ndc8_Activity_*`（及其对应的 `ID` / `Name` 图层）读取业务站点并按精确坐标或 50 mm 容差关联到对应路网节点，写入独立 `stations` 字段以避免与路网节点编号撞号。路线中心线依据首尾端点与节点圆心识别并按 NDC8 原始记录顺序与对应编号配对，兼容带方向箭头、零长度占位或省略无箭头占位的 DXF（含 `POLYLINE` 与 `LWPOLYLINE`），顶点顺序和弯道折线完整保留。箭头、定位标记、站点标注继续显示在底图中。路线中心线或业务站点数量与编号不一致、出现错位图元或站点无唯一对应节点时会提示错误。
- 「导出地图 JSON」使用下述第一版契约。DXF 坐标换算成米，保留原 CAD XY 原点，导入时比例尺设为 `1`。图纸和轨迹共用产生器位置、轴映射、缩放及旋转。原图缺少明确双向属性时，JSON 保留路线顶点顺序与独立编号。
- 普通 CAD 图纸可通过工具栏导入为参考图。NDC8 转换依赖原导出记录与图层，常规 CAD 线条无法单独确定 AGV 的业务节点和路径。

## 第一版 JSON 契约

导出的地图使用下列结构。坐标必须是有限数值；节点、轨迹 ID 在同一地图内唯一；轨迹端点必须引用已声明节点。

```json
{
  "schemaVersion": 1,
  "id": "factory-line-1",
  "name": "一号产线 AGV 地图",
  "nodes": [
    { "id": "P01", "name": "取货点", "businessType": "pickup", "x": 0, "y": 0 },
    { "id": "P02", "name": "卸货点", "businessType": "dropoff", "x": 12, "y": 8 }
  ],
  "tracks": [
    {
      "id": "T01",
      "name": "主路线",
      "fromNodeId": "P01",
      "toNodeId": "P02",
      "bidirectional": true,
      "points": [
        { "x": 0, "y": 0 },
        { "x": 12, "y": 0 },
        { "x": 12, "y": 8 }
      ]
    }
  ],
  "stations": [
    { "id": "633", "name": "633", "nodeId": "P01", "businessType": "焊接线站点", "x": 0, "y": 0 }
  ]
}
```

字段约定：

- `businessType` 是可选业务分类字符串，当前预置示例使用 `pickup`、`dropoff`、`station`、`charging`、`waiting`；渲染不依赖该分类。
- `bidirectional` 表示路线是否允许反向通行；缺省或 `false` 按 `fromNodeId → toNodeId` 单向处理。它不影响轨迹显示，但参与任务最短路径计算。
- `points` 是可选的完整有序折线，至少两个点，适合 CAD 中的多段线。省略时使用 `fromNodeId`、`toNodeId` 对应业务节点的 XY 坐标绘制直线。
- `stations` 是可选的业务站点列表（如 NDC8 的 `Ndc8_Activity_*`），每项通过 `nodeId` 关联到 `nodes` 中的路网节点。站点编号与路网节点编号独立命名空间，MQTT 任务端点取站点 `name`，寻路端优先按 `stations.name` 映射到 `nodeId`（可复用 `resolveAgvMapNodeId`），避免与路网点撞号；旧站点 `id` 和路网节点 `id` 仍作为兼容回退。
- 当前校验上限为 4096 个业务节点、8192 条轨迹、每条轨迹 2048 个折线点、4096 个业务站点。

类型定义和校验入口位于 `src/editor/model/agvMap.ts`，内置地图注册位于 `src/editor/model/agvMapLibrary.ts`。内置地图随场景保存 ID 与显示配置。DXF 导入地图另随场景保存节点与路线，底图从工程内的 DXF 副本读取。

## AGV MQTT 位姿驱动

设备模型的 `deviceType` 或模型包 `dataDriven.device.devType` 声明为 `agv`/`agv_xxx` 后，模型 Inspector 会显示「数据驱动」并复用同一 AGV 位姿驱动；快照仍按原始协议类型精确匹配。旧场景只有 `modelAsset.deviceType='agv'` 时也会补建默认绑定，不要求重新导入模型。

标准配置流程：拖入 AGV 模型并校准、隐藏模板实例 → 创建 AGV 产生器并关联模板、选择地图和点击事件 → 运行预览接收 MQTT。产生器只在运行态创建动态设备，隐藏模板自身不参与设备驱动。

- 默认模板和条件规则模板都从场景实例中选择，模板必须带 `modelAsset`，最终设备类型必须是 `agv` 或以 `agv` 开头（例如 `agv_forklift`，大小写不敏感）；非 AGV 实例不会出现在下拉选项中，旧配置引用失效时会在面板和运行日志中提示。
- 「条件模板规则」复用模型生成器的属性名/属性值匹配方式：按列表顺序取第一条命中，属性名读取标准快照 `fields`，也支持顶层 `sourceId`、`deviceType`、`assetCode`；数字、布尔值和字符串统一转为字符串并去除首尾空格后精确比较。规则模板留空表示使用默认模板，未命中任何规则也使用默认模板。
- 规则只在首次生成实例时求值，存活期间的后续字段变化只保活，不替换模型。规则模板的模型、参数、脚本、车头轴和完整 Transform 均从各自场景实例派生；动态实例的遥测设备类型跟随默认模板，因此规则只改变视觉配置，不改变原消息的 topic 匹配协议。

- 模型包通过 `dataDriven.device.modelForwardAxis` 声明 GLB 局部车头轴默认值；模板的 `telemetryBinding.modelForwardAxis` 可覆盖该默认值，「恢复模型默认绑定」会回到包内声明。可选 `+X`、`-X`、`+Z`、`-Z`，缺省 `+X`，动态实例继承模板最终配置。
- 角度协议约定 `r=0` 时车头指向场景 `+X`，顺时针为正。驱动根据模型正方向轴补偿初始朝向，不把 `movement_x` 当作位移量。
- 动态 AGV 的 `x/y` 是产生器地图坐标：先按产生器的 `xAxis/yAxis/scale` 换算，再应用产生器实体的完整 Transform。地图原点就是产生器位置，比例尺和轴映射与地图显示一致。未关联地图的静态 AGV 仍按场景世界 `X/Z` 驱动。`z=null` 不参与整机移动；只更新一个平面字段时保留上一目标的另一地图通道。当前不做路网吸附或路径约束。
- 首个有效位姿直接落位，避免动态实例从模板位置滑入；后续 `x/y/r` 采用延迟一个采样点的分段线性插值：收到新样本后，从当前画面位置向新目标播放，时长取相邻样本 `sourceTimestamp`（缺失时 `receivedAt`）的实际差值，位置速度为两点距离除以该时长，不做缓入缓出或阻尼减速。报文提前到达时从当前插值位置承接，车头沿最短转角按同一时长旋转。正常连续推送时画面约落后一个采样周期；该平滑只跟随 MQTT 实时位姿，不代表沿路网自动寻路。
- `normal=false`、非零 `errorCode` 或 `mode=0` 时冻结位姿；数据断流时不接受新目标，但已开始的短过渡会继续到最近目标后停止。动态实例收到 `mode=0` 后按 AGV 离线协议销毁，也继续兼容通用 `status=offline`。
- `task_begin_point` 与 `task_end_point` 同时存在时，动态 AGV 先将两个站点 `name` 反查为 `stations.nodeId`，再按地图节点和轨迹方向计算累计折线长度最短的路线，结果包含节点序列、轨迹 ID、完整折线和地图单位长度；相同任务起终点复用缓存。车辆进入与当前路线起点不同的节点触达半径后，先校验当前路线：若该节点位于当前路线中且后续轨迹仍贯通，直接保留原轨迹 ID 和折线并截取剩余部分，只更新诊断信息和裁剪进度，不重建高亮；若该节点不在当前路线中，但车辆到当前折线的最近距离不超过触达半径，则视为密集或重叠路段上的途经节点，同样保持当前路线。仅当车辆实际离开当前路线并触达其他节点，或原剩余轨迹失效时，才以该节点为新起点、原任务终点为目标重新计算有向最短路线。触达半径按场景米配置，默认 0.2 米，检测使用车辆当前地图坐标而非严格等于节点 `x/y`，且不改变车辆实时位置。触及终点后路线长度为零并释放高亮。`bidirectional=true` 的轨迹可反向使用，其余轨迹只允许正向。任一站名称不存在或路网不可达时返回无路线，不用两点直线替代。点击动态 AGV 后，只读「运行时诊断」展示路线摘要或不可达原因。贯通路线可按产生器配置显示任务高亮，支持流光路径、流动箭头、路径逐段点亮和管道流动四种样式，并可配置剩余路径颜色、线宽、不透明度、流动速度和数量。流动速度使用场景米/秒，箭头与流光按 `速度 × 时间 ÷ 路线场景长度` 推进，因此长短路线上的实际移动速度一致；设为 0 时停止流动，数量只控制显示密度。旧 `duration` 整路周期配置不再参与计算，未保存速度时使用默认值 1.5 米/秒。运行时将小车当前地图坐标投影到当前任务折线，最近投影点之前的路线和箭头直接隐藏，只显示车辆到终点的剩余部分；移动和正常途经节点时只更新进度与动画，不重建路线几何，只有任务变化或真实偏航重规划时才替换高亮几何。路线不覆盖 `x/y/r` 实时位置，也不让车辆脱离真实上报位置自动行驶；无路线、零长度路线或关闭高亮时不创建高亮网格。
- `signalBits=1` 表示台上有货：动态 AGV 继承模板实体的 `cargoGeneratorId`，按对应模型生成器及当前快照创建/更新货物，并保存 `containerCode`、`task` 供规则匹配和点击元数据使用；`signalBits=0` 时销货，字段缺失时保持原货物。`command=6` 表示放货完成，即使光电仍有读数也按完成状态清货。
- `command` 驱动取放货阶段：`1/2` 取货中/申请取货保持低位，`3` 取货完成抬升，`0` 按是否有货保持运输高度，`4/5` 放货中/申请放货下降，`6` 放货完成回低位；缺少 `command` 时按 `signalBits` 保持兼容。模型包通过 `dataDriven.cargo.lift.followNodes` 声明全部随动节点，`distance/speed` 声明行程（米）和速度（米/秒）；未声明随动节点时使用 `cargo.deckNodes`。载货台面与伴随结构可以不同，货物支撑点始终取升降后台面节点及子网格的合并包围盒顶面中心，并随 AGV 世界位置和朝向逐帧更新。节点未完整声明或解析不到时记录一次配置警告，不使用整机包围盒猜测台面。动态实例销毁、离线或退出预览会同步清理货物并恢复节点基线。旧 `cargo.nodes`、`cargo.lift.nodes` 字段继续按原顺序回退兼容。
- 其余 `command`、`deviceType`、`batteryLevel`、`message`、`timestamp` 等原始字段保留在标准快照和运行时诊断中；当前不执行独立装卸动画。
- AGV 产生器按模板的 `deviceType` 注册，首条带 `s` 的 MQTT 消息生成实例，后续消息按 topic 中的设备号及完整 `sourceId/deviceType/assetCode` 驱动对应实例。动态实例在生成时读取产生器的地图放置配置及对应地图定义。
- 动态 AGV 可点击。点击后右侧显示「动态 AGV 实例」及只读「数据驱动」模块，包含来源产生器、继承配置、在线状态、topic、时间和最新 MQTT fields；产生器配置的高亮、聚焦和图表点击事件继续执行。动态选区和实例快照不写入场景文档，实例下线或退出预览即清理。

可用 `npm run demo:spawn:mqtt` 发布包含上述字段的 AGV 演示数据，或先运行 `node scripts/simulate-device-spawn-mqtt.mjs --once --stdout` 检查报文。领域回归入口为 `npm run test:agv-drive`，产生器与地图回归入口为 `npm run test:agv-spawner`。
