# 高精度零件爆炸图：三端 UI 与交互原型

这是拟新增能力的设计交付，不是已接入生产的功能。三维使用仓库现有 Babylon.js 9.12.0 原生 WebGL，模型为程序化驱动总成示意，全部指标与告警为模拟样本。未加载真实高精度 GLB、未接中台接口、不写入实际工程。正式实现按已复核方案使用官方 Babylon Viewer 加载固定版本的分件高模。

打开 `设备爆炸图-三端交互原型.html`，在顶部切换三个界面。该文件包含样式、代码与 Babylon 运行代码，不依赖 CDN。需要支持 WebGL 的现代浏览器；WebGL 不可用时显示错误，不启用软件回退。

展示顺序是“大屏效果 → 编辑器 → 中台配置”；实际准备顺序是“编辑器配置并发布 → 中台配置 → 大屏使用”。

## 1. 大屏里看到什么

- 左侧保留场景低模总览、当前设备和关联告警。
- 独立高模工作区展示设备与固定版本、零件树、三维模型、零件数据和展开滑块。
- 点击模型或零件树，选择、高亮与右侧数据同步。示例电机 `drive.motor`、减速机及轴承有模拟指标，其他零件显示“未配置零件数据”。
- 支持 0–100% 展开、整体取景、聚焦、隔离、标注、复原、取消零件选择和关闭。
- 点击温度告警，反向打开 CV-021 并定位驱动电机。
- 滑块与镜头只改变查看状态，不发起业务查询。取消零件选择不展示旧值；关闭保留设备选择并把焦点还给入口。
- 默认画面用于展示“告警定位后的展开状态”。普通打开从装配姿态开始，先选零件再显示零件样本。
- 界面数值、趋势及时间全部标注模拟；曲线提供键盘可访问的样本提示与数据表。

## 2. 数字孪生编辑器怎么做

已有入口来自当前源码，新增项在原型中标注：

1. 在场景层级选设备，在现有 `Inspector → Model Asset` 确认“资产编号”；拟新增“高精度详情”分组。
2. 绑定独立高模、固定版本及适用配置。原型可切换 6 米有站台 / 10 米无站台，错误配置会阻止暂存。
3. 在新增零件树和参数表中配置 `partKey → 高模节点`，选择方向、距离和固定组。复用既有“零件爆炸图 / 结构分组”的底层逻辑，不直接沿用低模节点路径。原型支持修改所选非固定件的方向和距离并立即预览。
4. 经已有 `POI库 → 点击事件绑定 → 事件列表 → 点击 → 事件效果`，增加“打开设备详情”动作；再“运行”验收、“保存场景”、“发布到数据中台”。原型按钮只校验和暂存内存，不实际发布。

已有编辑器爆炸特效的进度控件会保存配置；本设计的大屏与独立预览滑块必须走运行时状态，不能复用该持久化提交链。绑定、零件规则与点击配置经 commands 写入 SceneDocument，并支持撤销/重做。

## 3. 数据中台大屏怎么配置

1. 使用已有组件库 `Babylon Runtime`。在属性面板选择 `运行方式 → 发布 Viewer（支持大屏联动）`。
2. 绑定当前大屏项目，沿已有 `当前项目稳定版本 / 固定已完成发布记录` 选择发布内容。稳定模式可跟随新的稳定发布，每份发布内部的高模引用保持固定；固定模式固定完整发布记录。
3. 在新增“高模详情”分组启用展示。高模与零件定义从孪生工程发布内容读取，中台不再次上传高模、不重复编排爆炸结构。
4. 配置事件路由：设备点击打开详情；零件选择更新依赖零件的数据源；告警点击使用设备编号和 `partKey` 定位设备及零件。“启用详情”是展示开关，设备点击入口来自编辑器动作。
5. 在数据源已有“点击参数策略 / 声明的点击参数”中，声明零件源实际依赖的输入。再增加“必填参数未齐不请求”门禁。现有 declared 策略本身只有过滤功能，没有必填门禁；不得标成现成能力。

原型采用宿主先依据工程绑定投影设备数据键的拟议契约，示例为：

| 字段 | 示例值 | 来源 |
| --- | --- | --- |
| assetCode | CV-021 | 场景设备资产编号 |
| namespace | warehouse_demo | 设备数据绑定 |
| deviceType | conveyor | 设备数据绑定 |
| deviceNo | CV021 | 显式绑定，不自动等同于 assetCode |
| partKey | drive.motor | 当前零件或告警装配位 |

零件源声明 `namespace/deviceType/deviceNo/partKey`；设备级源只声明设备键；全局源忽略点击。声明的必须是**映射前的输入字段名**：如果沿用现有 `assetCode → HTTP Body.deviceNo` 的方式，则声明 `assetCode` 与 `partKey`，不能只声明映射后的别名 `deviceNo`。

`modelId/versionId/projectId/publishTaskId` 等后端 Long ID 必须用字符串。此原型不模拟身份认证、生产资源下载或真实发布。

## 交互验证范围

已使用本机 Edge 与 Playwright 完成 22 项原型检查：三维展开/复原、直接点击模型与树选择、隔离、告警定位、缺失数据、关闭清理及焦点恢复、编辑器方向/距离跨选择保持与配置不匹配、中台绑定切换、遗漏 partKey 阻止应用、375px 三屏无横向溢出，以及断网时单文件无 HTTP/CDN 请求启动。检查记录在 `screenshots/verification.json`，三张实际浏览器截图在同一目录。

独立 Node 语法检查与单文件构建成功，交互过程中没有未捕获 JavaScript 错误。未运行业务 npm 测试、类型构建、Electron 或真实资源性能验收：本次仅新增独立 UI 文档原型，未修改业务运行代码。

这些检查只证明原型交互，不证明实际高模精度、生产协议、资源发布链、真实中台查询、Electron IPC 或性能已通过。

## 原型源文件

- `index.html`：开发入口。
- `prototype.js`：三屏界面及内存交互状态。
- `prototype.css`：运行端、编辑器深色与中台浅色设计。
- `assembly.js`：程序化 Babylon 装配示意、场景示意和查看交互。
- `build.mjs`：使用现有 rolldown 生成单文件 HTML，不安装依赖。
- `vite.config.mjs`：独立原型预览配置，不加载编辑器业务入口。

重新生成单文件，在仓库根目录运行：

```bash
node docs/inspection-ui-prototype/build.mjs
```

UI 依据为当前两仓源码与通用桌面可访问性规范。UI/UX 技能检索未获得已核验的工业桌面专用模板，因此没有直接套用返回的落地页结构。趋势图单一系列颜色已在深色图表背景上通过技能脚本校验。
