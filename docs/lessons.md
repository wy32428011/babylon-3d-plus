# 实现经验

## 模块化 WebGPU 必须验证真实绘制与异步释放（2026-10-29）

- Babylon 9.12 的 GPU 粒子平台注册不等于 Compute 引擎扩展已注册；还需显式加载 `Engines/WebGPU/Extensions/engine.computeShader.js`，否则能力检测通过但 ComputeEffect 不存在。以实际粒子就绪及非空像素确认，而不是仅检查 `supportComputeShaders`。
- CSM 的 `onBeforeRenderObservable` 传 layer，但 RTT unbind 后的 `onAfterRenderObservable` 仍传 faceIndex=0；分层诊断须保存实际 before pass 并限定在 bind/unbind 内，排除同样发送通知的 readiness 检查。不能仅用两个事件的同名数字配对。
- 异步视口的资源预热发生在宿主取得返回值之前；取消必须在工厂内立即释放已创建视口，不能只在宿主 cleanup 里检查尚为空的 ref。更换 context 类型须换 canvas，并以 ready generation 重放首次同步，保留相机/选择和未启动请求，已取消的业务任务不能自动重做。

## 编辑器离开与文件读取需要跨边界保持同一身份（2026-10-28）

- 场景离开许可绑定会话与文档内容，异步确认、保存或加载后再次核对；窗口关闭需等 renderer 明确回复，不能到 `closed` 才检查未保存内容。
- 桌面 IPC 的主 frame 不等于可信页面，入口校验同时绑定实际窗口与 URL；普通资产先核对真实路径，再把同一文件句柄交给响应流，避免检查后重新按路径打开。

## 静态图片审计应绑定真实视口（2026-10-26）

- 通过CDP逐属性扫描整个React界面，会把模型库UI规模转化为大量跨进程等待；本例16路并发仍未在180秒内完成运行时发现。
- 从唯一场景canvas沿owner定位runtime，并核验engine的实际绘制canvas，再执行原有实例/字节校验；保留只读descriptor与Proxy拒绝，补充阶段进度和有限超时。本例18槽位/2张图片完整核对约99秒完成，不能把审计耗时当加载或GPU指标。

## Babylon 按需导入须保留碰撞协调器注册（2026-10-26）

- 手动漫游调用 `moveWithCollisions()` 时，单独导入 Mesh/Scene 不会注册默认碰撞协调器，`Scene.CollisionCoordinatorFactory` 会抛出缺少 `DefaultCollisionCoordinator` 导入的异常。
- 在公共副作用入口导入 `@babylonjs/core/Collisions/collisionCoordinator.js`；该入口调用 `RegisterCollisionCoordinator()`，仅导入类型或纯实现不能替代注册。

## Babylon共享几何与局部缓冲更新须明确所有权（2026-10-26）

- 触发：从完整独占容器改为共享Geometry，以及将thinInstance全量上传改为局部上传。
- 原因：AssetContainer会直接dispose其geometries清单；9.12的Buffer.updateDirectly可能丢弃恢复镜像，thinInstance世界矩阵还可能保留旧缓存。只比较JS对象或数组不足以证明正确。
- 修复：共享源lease持有到最后实例释放，共享Geometry不进入工作容器销毁清单；局部上传同步权威数据/缓存，并由受控恢复监听重传，监听随Mesh释放。
- 预防：分别核对取消/淘汰/释放、实际GPU字节、全量与局部像素及context restore，不把少上传的字节当作FPS收益。

## 加载期派生缓存写回须维护资源事务快照（2026-10-26）

- 触发：编辑器天空 ENV 已 ready、实际首帧通过，进度到 100% 但加载遮罩仍保留。
- 原因：派生 ENV 写回创建新的场景对象，却未同步推进 transaction/recovery 的 `after`；事务收尾被文档身份 CAS 拒绝，准备状态仍完成并停止轮询。
- 修复：缓存写回与匹配当前文档的事务快照在同一次 Store 更新中推进，实体天空和旧场景级天空共用；不改历史、原始快照，也不认领已失配的旧事务。
- 预防：审查加载期非业务编辑的文档替换时，同步检查资源事务引用；完成条件不能只看百分比或天空 ready，还要确认事务已结算、遮罩已退出，不能通过放宽 CAS 或强行隐藏遮罩规避。

## 天空准备的取消、缓存与开发懒加载边界（2026-10-26）

- 触发：快速切换可能把已取消任务留在队列；提交阶段取消未传到主进程；首次加载转换 Worker 又触发 Vite 预构建重载。
- 原因：只取消消费者而未结算等待项，进度回调之后漏查取消，去重键未隔离场景会话；Worker 入口不在开发依赖扫描中。
- 修复：未启动任务立即出队，持有令牌期间即时传播取消，提交回调后再检查；同源任务按场景会话隔离；启动扫描显式包含转换器和 Worker。
- 预防：定向覆盖取消队列容量、commit回调及提交中取消、跨会话请求；旧URL先解析且按源SHA给HTTP缓存分版；派生写入拒绝祖先Junction，缓存回收只删除无会话租约的历史产物。

## 基线对照 worktree 不得用 junction 共享 node_modules 后再强制删除（2026-10-25）

- 触发：为区分“既有失败”与“本次改动失败”，在 HEAD 建临时 `git worktree` 并用 junction 指向主仓库 `node_modules`；对照完成后执行 `git worktree remove --force`，主仓库 `node_modules` 被清空。
- 原因：强制删除 worktree 会递归清理目录，junction 目标内容被一并删除；与单独 `rmdir` junction 不同，且删除前未确认 junction 已解除。
- 修复：按 `package-lock.json` 执行 `npm ci` 还原（Electron 运行时在首次 `require('electron')` 时重新下载），核对包数量、版本及无 postinstall 补丁，`package.json`/`package-lock.json` 保持不变。
- 预防：基线对照改用独立目录安装依赖或只复制必要的 `dist-electron`/配置；若必须使用 junction，必须先单独移除并校验目标仍存在，再删除 worktree；破坏性清理前先列出目标内容。

## 原生天空盒的 ENV 编译、验证入口与测试服务陷阱（2026-10-25）

- 触发：把天空盒改为编辑器编译 Babylon `.env`、运行时只加载 ENV 后，出现四类“看似功能错误、实为验证环境错误”的问题：离屏编译的 ENV 重新载入永不结束；正交相机下天空消失却被弱断言放过；Playwright `_electron.launch` 超时；使用 `configFile: false` 的 Vite 测试服务模块加载超时。
- 原因：Babylon 9.12 的 `_OnImageReadyAsync` 在 `engine.scenes` 为空时直接返回，仅有离屏 Engine 而无 Scene 时 CubeTexture 永远不 ready；天空网格在正交投影下需要单独的背景投影，只靠“网格存在/像素非空”断言无法发现，必须看截图并断言角落像素不等于清屏色；本机当前 Electron/Playwright 组合在显式指定 `executablePath` 时未注入主进程 loader，改用包默认入口后可启动；`configFile: false` 的测试服务不继承 `vite.config.ts` 对 `output/` 的监听忽略，仓库 `output/` 有 7 万文件，监视器扫描使单次模块加载超过 60 秒。
- 修复：编译器内创建并在 finally 释放宿主 `Scene`；运行时补正交背景投影并加角落像素断言；UI 测试不传 `executablePath`，自带独占端口的 Vite 服务（`tests/helpers/skyboxViteServer.mjs`）并关闭 watcher，只关闭自己创建的服务；使用 Vite SSR 的测试统一 `server.watch: null`。
- 预防：真实 GPU/Electron 验证必须保留截图和像素断言；新增 Vite 测试服务默认关闭监视；升级场景文件版本时同步更新各测试中的“未来不支持版本”常量，并让假 Viewer 模板携带真实能力清单。

## 中台工程首次失败须同时覆盖占用恢复与空目录重试（2026-10-25）

- 触发：工程包 `extracted/Assets → materialize/staged/Assets` 在 Windows 抛出 `EPERM`；直接重试又可能因初始化空目录被误判为未绑定用户内容而失败。
- 原因：工程物化、推广和回滚漏用了资源同步已有的 Windows 有限退避；初始化先于下载且正式绑定后写，失败清理后会保留空目录。
- 修复：所有事务 rename 对 `EPERM/EACCES/EBUSY` 有限重试；打开等待可取消、恢复操作不受已取消 signal 阻断。仅确定来源目录中的白名单空骨架允许重试，不放行文件、未知目录、junction 或待恢复事务目录。
- 预防：通过真实 Electron 打开入口验证暂时/持续占用、原错误保留、取消回滚和恢复目录保留，并验证首次下载失败后可再次请求；不能以删除用户目录、预写成功绑定或回退空场景来规避问题。构建与故障注入回归不代表真实桌面已加载修复。

## Electron 开发启动须经过包的运行时准备入口（2026-10-24）

- 触发：安装依赖后 `dev:electron` 完成 TypeScript 重建，却没有窗口且 Vite 继续运行。
- 原因：Electron 42.4.0 包通过首次 `require('electron')` 按需下载运行时；硬编码 `node_modules/electron/dist/electron.exe` 绕过准备，启动器又静默吞掉 spawn error。`缺少 N/M 个 Electron 产物` 仅指编译输出，不能据此判断 Electron 二进制已安装。
- 修复：启动服务前使用官方包导出的路径；准备或启动失败必须显示原因、非零退出并回收本次资源。
- 预防：保留首次准备、包安装失败及不存在可执行文件三类隔离回归，并实际运行完整 npm 入口验证窗口；编译产物、Electron 运行时和页面就绪分别核对。

## 本机工具路径保存需要精确检测候选文件

- 触发：将 Blender 路径从手工 JSON 配置移入编辑器界面，旧的引擎发现器会在手动路径失败后继续查找其他安装。
- 原因：复用自动发现的成功状态来验证输入，会把另一份 Blender 的成功误认为用户所选路径可用；旧查询晚返回也可能覆盖显式重新检测的设备缓存。
- 修复：浏览仅更新草稿，检测和保存精确检查所选文件；保存前重新探测版本与设备并保留旧配置，区分输入、当前生效路径及来源；缓存写入前核对当前版本请求身份。
- 预防：覆盖无效路径不回退、不覆盖文件，旧请求晚返回、环境变量优先、自动查找恢复和配置/烘焙互斥，并用隔离用户目录执行真实 Electron/Blender 与发布验收。

## 场景文件升级必须统一所有读取和预处理入口

- 触发：统一光照保存器升为外层 version 6，本地场景打开在资源准备 67% 处报“场景模型更新格式无效”。
- 原因：只修改保存器和部分解析器，资源准备、SOURCE 工程包检测、发布模型/身份恢复和发布快照仍有独立的 1–5 白名单；此前无中台配置的 UI 验收走了另一条恢复路径，未覆盖该门禁。
- 修复：共享 `sceneFileVersion` 严格合同覆盖所有场景读写，光照预处理在升级前拒绝未知版本；业务资源和结构校验继续保留。
- 预防：除序列化往返外，使用已配置本地接口的真实打开入口，覆盖旧文件、新文件、工程包和发布准备；等待新场景会话的资源就绪与真实首帧。纯资源夹具须保留实体 id；既有测试期待迁移时只能调整明确的格式差异，业务字段仍逐项对比。

## 并行重构清理必须确认当前文件用途和写域

- 触发：旧命名的环境测试已由运行时任务改为新光照行为，整合清理仍按早期旧文件清单删除它。
- 原因：清理依据早于文件改写，按名称推断用途，没有先冻结当前删除清单与写域。
- 修复：将六项新受光、材质和天空盒回归保留到明确的 canonical 新文件名，重跑通过并登记入口。
- 预防：删除前核对当前调用、文件版本与负责人；冻结后由单一负责人清理，保留新契约覆盖，不能以旧文件名判断测试失效。

## 场景模型总量应与渲染裁剪分离

- 触发条件：统计全场模型面数、实例数量等内容总量，场景使用逻辑阵列、共享源几何和视锥裁剪。
- 原因：`scene.meshes` 可能移除脚本宿主，`thinInstanceCount` 可能只保留当前视锥可见实例；渲染集合不代表完整场景。双面/阴影重复绘制也不代表新增几何。
- 修复：从业务登记及完整逻辑实例累计有效源几何；生成物和环境分别纳入，模板/代理去重，计数随结构或参数变化失效。
- 防止回归：覆盖隐藏父组、相机移出视野、参数变体、生成组合和货箱增删；总数不得随纯相机操作变化。

## 新场景会话需要首份运行时快照

- 触发条件：重开同一文档 ID，编辑器清空运行快照，运行时按数值去重通知。
- 原因：文档 ID 与统计值可能均不变，运行时不再回调，新会话会一直停留在统计中。
- 修复：同步后主动发布当前快照，并以场景会话校验异步写回。
- 防止回归：验证空场景及已有模型场景按同 ID 重开，统计仍从加载态进入正确结果，且不改变文档或撤销历史。

## 去掉强制世界矩阵计算必须覆盖同帧再次同步

- 触发条件：为减少编辑辅助标记的稳态成本，将 `computeWorldMatrix(true)` 改为默认调用。
- 原因：Babylon 会按相同 renderId 快退；同一帧内父级或节点再次改变时，单纯依赖默认调用可能留下旧矩阵。
- 修复：缩放相同时不写入，使用 `computeWorldMatrix(!node.isSynchronized())`，只在真实失同步时强制刷新。
- 防止回归：覆盖同 renderId 内重复 `sync`/`syncPresentation`、父级变换、相机与视口变化；断言读取 `worldMatrixFromCache`，避免测试自身补算掩盖遗漏。

## DOM 样式去重需要考虑浏览器规范化

- 触发条件：逐帧比较并写入颜色、阴影或变换样式。
- 原因：浏览器可将 `#rrggbb` 规范化成 `rgb(...)`，直接比较输入字符串与 DOM 值会继续重复写；只记输入又可能漏掉外部改动。
- 修复：同时保存请求值与应用后的实际值，两者都一致才跳过，缓存按样式对象弱引用保存。
- 防止回归：验证规范化颜色在稳定帧无写入，外部样式改动能纠正，动态位置、尺寸和隐藏恢复仍逐帧生效。

## 运行可视化观察不得提前建立业务缓存

- 触发条件：为设备箭头增加逐帧运动摘要，空载时主动调用原业务的输送轴解析器。
- 原因：解析器按绑定签名缓存失败结果；层模型晚就绪时，观察分支提前缓存空轴，原取货逻辑随后会把两个工位都放到台面中心。
- 修复：运动摘要只读取原动作路径已建立的有效缓存，不能为了显示额外触发寻址或改写业务状态。
- 防止回归：覆盖连续空载帧不写轴缓存，以及同一绑定签名下层模型晚就绪后取货仍解析独立工位。


## 集中配置需要可复用规则与可见来源

- 触发：用户要求在统一位置管理光照/烘焙配置，并让同资源的新实例继承。
- 原因：现有批量编辑只是把值写到当前选中实体；新对象没有可继承的场景规则，也难以区分默认值和已有例外。
- 修正：在场景保存规则，在同一个管理器显示有效值、来源、影响范围与例外；旧实体值保留为例外，恢复继承必须明确到字段或部件。
- 预防：验收同时覆盖已有和后续新增实例；自动分类底值不能含旧手动覆盖，否则恢复继承后仍会受到污染；分组复制必须处理规则的 folderId 作用域。

## 增量编译退出成功不代表产物可启动

- 触发：共享源码为直接类型剥离测试使用相对 `.ts` 导入，启用扩展重写后，Electron 仍因已缓存产物中的 `.ts` 引用启动失败。
- 原因：增量缓存认为输出已齐全而未重发射；仅检查文件存在和编译退出码无法识别不可交付的相对导入。
- 修复：解析实际 JS/CJS/MJS 产物的导入，发现未交付的 TS 目标时强制重建一次；重建后仍无合法目标则明确失败。
- 预防：覆盖 `.ts/.tsx/.mts/.cts`、合法已交付目标和示例文字，并用真实 Node 加载验证；完整输出继续使用增量编译。

## 隐藏源几何的光照代理必须读取本帧真实世界矩阵

- 触发：源 Mesh 因烘焙派生几何接管而退出主渲染，同一 renderId 内动作或逻辑实例布局仍会更新位置。
- 原因：无 force 的 computeWorldMatrix() 可能直接返回本帧缓存；回归中源 position.x=3，但 sourceWorld、pivot 和 proxyWorld 仍为 identity。
- 修复：在确实需要读取源变换时使用 computeWorldMatrix(true)，派生 Mesh 放在业务模型根节点之外。
- 预防：通过权威阵列 revision 和 carrier 变换缓存跳过未变化静态实例的读取，不通过使用旧矩阵或抽样检查降低成本；保持实例重排、动作后同步和清除恢复回归。

### 光照烘焙按实际产物验证绕序与纹理密度

- 触发：实际图集存在且UV合法，柱子却全黑；或texelsPerMeter数值未变，但空间分片后细节仍不足。
- 原因：Babylon左手绕序在坐标反射后再次无条件翻面，产生与自定义法线相反的面朝向；按世界表面积估方形UV图块也忽略了非均匀缩放和UV岛填充率。
- 修复：根据真实输入法线与面朝向导入，保留原导出索引语义；用世界尺度展开并按UV到世界的实际Jacobian分配图块，超页继续切分。

- 做法：在原异常边界内记录同步attempt与failed，保留可选调用表达式、getter单次读取和receiver；原本不await的Promise继续不等待。诊断sink失败独立记录，不能覆盖原脚本错误。
- 排名：按完整资源身份在私有内存汇总，公开只保留文件名和运行期ID；达到内存上限须标记排名不完整。单次真实读回仅证明可观测性，不证明性能提升。

## Blender嵌入解释器不一定遵循Python环境变量（2026-10-25）

- 实测Blender5.2.2 `sys.flags.ignore_environment=1`，即使env含PYTHONDONTWRITEBYTECODE=1，startup dont_write_bytecode仍false；普通Python子进程通过不能替代实际嵌入解释器。
- 修复：仅受控helper导入期间显式置sys.dont_write_bytecode并finally恢复，实际Blender成功/抛错/真实PNG微回归，保持任务目录严格拒绝未知目录与脚本，不把__pycache__加白名单。

## Electron原生ESM测试入口不要顶层等待app ready（2026-10-25）

- 两个独立工具实测：bootstrap顶层`await app.whenReady()`会使入口模块未结束、ready无法推进，Playwright launch超时且尚未创建renderer；这不是GI或产品启动失败。
- 使用`app.whenReady().then(async () => { ... })`注册式初始化，并等待明确host/window就绪receipt；或复用已通过的主入口bootstrap。新工具保持独立userData、核实owned PID退出、删除精确临时bootstrap，失败目录保留。
- 若bootstrap还要导入产品main，必须在ready前完成该模块求值，使`protocol.registerSchemesAsPrivileged`来得及注册；只把需要ready的查询放进回调。POST-only无窗口入口可以在ready回调运行，两条路径分别测试，不能把主入口也移入ready回调。
- 2026-10-26：实际主窗口加载 `preload.cts` 生成的 `preload.cjs`；只更新同名 `preload.ts` 不会接通桌面API。类型检查与直接调用服务通过不能代替实际窗口到IPC的连通检查。复用旧UI脚本时须按当前惰性分类入口触发，不能等待已不再自动刷新的Store列表。
