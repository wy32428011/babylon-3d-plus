# 实现经验

## 场景文件升级必须统一所有读取和预处理入口

- 触发：统一光照保存器升为外层 version 6，本地场景打开在资源准备 67% 处报“场景模型更新格式无效”。
- 原因：只修改保存器和部分解析器，资源准备、SOURCE 工程包检测、发布模型/身份恢复和发布快照仍有独立的 1–5 白名单；此前无中台配置的 UI 验收走了另一条恢复路径，未覆盖该门禁。
- 修复：共享 `sceneFileVersion` 严格合同覆盖所有场景读写，光照预处理在升级前拒绝未知版本；业务资源和结构校验继续保留。
- 预防：除序列化往返外，使用已配置本地接口的真实打开入口，覆盖旧文件、新文件、工程包和发布准备；等待新场景会话的资源就绪与真实首帧。纯资源夹具须保留实体 id；既有测试期待迁移时只能调整明确的格式差异，业务字段仍逐项对比。

## 并行重构清理必须确认当前文件用途和写域

- 触发：旧命名的环境测试已由运行时任务改为新光照行为，整合清理仍按早期旧文件清单删除它。
- 原因：清理依据早于文件改写，按名称推断用途，没有先冻结当前删除清单与写域。
- 修复：将六项新受光、材质和天空盒回归保留到明确的 canonical 新文件名，重跑通过并登记入口。
- 预防：删除前核对当前调用、文件版本与负责人；冻结后由单一负责人清理，保留新契约覆盖，不能以旧文件名判断测试失效。

## 场景模型总量应与渲染裁剪分离

- 触发条件：统计全场模型面数、实例数量等内容总量，场景使用逻辑阵列、共享源几何和视锥裁剪。
- 原因：`scene.meshes` 可能移除脚本宿主，`thinInstanceCount` 可能只保留当前视锥可见实例；渲染集合不代表完整场景。双面/阴影重复绘制也不代表新增几何。
- 修复：从业务登记及完整逻辑实例累计有效源几何；生成物和环境分别纳入，模板/代理去重，计数随结构或参数变化失效。
- 防止回归：覆盖隐藏父组、相机移出视野、参数变体、生成组合和货箱增删；总数不得随纯相机操作变化。

## 新场景会话需要首份运行时快照

- 触发条件：重开同一文档 ID，编辑器清空运行快照，运行时按数值去重通知。
- 原因：文档 ID 与统计值可能均不变，运行时不再回调，新会话会一直停留在统计中。
- 修复：同步后主动发布当前快照，并以场景会话校验异步写回。
- 防止回归：验证空场景及已有模型场景按同 ID 重开，统计仍从加载态进入正确结果，且不改变文档或撤销历史。

## 去掉强制世界矩阵计算必须覆盖同帧再次同步

- 触发条件：为减少编辑辅助标记的稳态成本，将 `computeWorldMatrix(true)` 改为默认调用。
- 原因：Babylon 会按相同 renderId 快退；同一帧内父级或节点再次改变时，单纯依赖默认调用可能留下旧矩阵。
- 修复：缩放相同时不写入，使用 `computeWorldMatrix(!node.isSynchronized())`，只在真实失同步时强制刷新。
- 防止回归：覆盖同 renderId 内重复 `sync`/`syncPresentation`、父级变换、相机与视口变化；断言读取 `worldMatrixFromCache`，避免测试自身补算掩盖遗漏。

## DOM 样式去重需要考虑浏览器规范化

- 触发条件：逐帧比较并写入颜色、阴影或变换样式。
- 原因：浏览器可将 `#rrggbb` 规范化成 `rgb(...)`，直接比较输入字符串与 DOM 值会继续重复写；只记输入又可能漏掉外部改动。
- 修复：同时保存请求值与应用后的实际值，两者都一致才跳过，缓存按样式对象弱引用保存。
- 防止回归：验证规范化颜色在稳定帧无写入，外部样式改动能纠正，动态位置、尺寸和隐藏恢复仍逐帧生效。

## 运行可视化观察不得提前建立业务缓存

- 触发条件：为设备箭头增加逐帧运动摘要，空载时主动调用原业务的输送轴解析器。
- 原因：解析器按绑定签名缓存失败结果；层模型晚就绪时，观察分支提前缓存空轴，原取货逻辑随后会把两个工位都放到台面中心。
- 修复：运动摘要只读取原动作路径已建立的有效缓存，不能为了显示额外触发寻址或改写业务状态。
- 防止回归：覆盖连续空载帧不写轴缓存，以及同一绑定签名下层模型晚就绪后取货仍解析独立工位。


## 集中配置需要可复用规则与可见来源

- 触发：用户要求在统一位置管理光照/烘焙配置，并让同资源的新实例继承。
- 原因：现有批量编辑只是把值写到当前选中实体；新对象没有可继承的场景规则，也难以区分默认值和已有例外。
- 修正：在场景保存规则，在同一个管理器显示有效值、来源、影响范围与例外；旧实体值保留为例外，恢复继承必须明确到字段或部件。
- 预防：验收同时覆盖已有和后续新增实例；自动分类底值不能含旧手动覆盖，否则恢复继承后仍会受到污染；分组复制必须处理规则的 folderId 作用域。

## 增量编译退出成功不代表产物可启动

- 触发：共享源码为直接类型剥离测试使用相对 `.ts` 导入，启用扩展重写后，Electron 仍因已缓存产物中的 `.ts` 引用启动失败。
- 原因：增量缓存认为输出已齐全而未重发射；仅检查文件存在和编译退出码无法识别不可交付的相对导入。
- 修复：解析实际 JS/CJS/MJS 产物的导入，发现未交付的 TS 目标时强制重建一次；重建后仍无合法目标则明确失败。
- 预防：覆盖 `.ts/.tsx/.mts/.cts`、合法已交付目标和示例文字，并用真实 Node 加载验证；完整输出继续使用增量编译。

## 隐藏源几何的光照代理必须读取本帧真实世界矩阵

- 触发：源 Mesh 因烘焙派生几何接管而退出主渲染，同一 renderId 内动作或逻辑实例布局仍会更新位置。
- 原因：无 force 的 computeWorldMatrix() 可能直接返回本帧缓存；回归中源 position.x=3，但 sourceWorld、pivot 和 proxyWorld 仍为 identity。
- 修复：在确实需要读取源变换时使用 computeWorldMatrix(true)，派生 Mesh 放在业务模型根节点之外。
- 预防：通过权威阵列 revision 和 carrier 变换缓存跳过未变化静态实例的读取，不通过使用旧矩阵或抽样检查降低成本；保持实例重排、动作后同步和清除恢复回归。

### 光照烘焙按实际产物验证绕序与纹理密度

- 触发：实际图集存在且UV合法，柱子却全黑；或texelsPerMeter数值未变，但空间分片后细节仍不足。
- 原因：Babylon左手绕序在坐标反射后再次无条件翻面，产生与自定义法线相反的面朝向；按世界表面积估方形UV图块也忽略了非均匀缩放和UV岛填充率。
- 修复：根据真实输入法线与面朝向导入，保留原导出索引语义；用世界尺度展开并按UV到世界的实际Jacobian分配图块，超页继续切分。
- 防止重现：逐面采样真实RGBM并与单对象基准对照，覆盖左右手/镜像；对最终叶几何检查面积、覆盖、属性与最小实际像素/米。不能以PNG存在、配置数值未改或总图非黑作为完整证明。

## 阴影缓存只跟踪实际影响遮挡的材质输入

- 触发：固定投影与静态几何不变，模型上的动态屏幕颜色仍导致全部静态 CSM 每帧重绘。
- 原因：PBR/Standard 的 `getAlphaTestTexture()` 在不透明路径也可能返回颜色贴图；无条件跟踪该 DynamicTexture 的帧号，把颜色变化误判成遮挡变化。
- 修复：逐 submesh 判断原生 alpha 测试/混合路径，仅跟踪实际参与遮挡的贴图、cutoff 和 UV 矩阵值；保留动态 alpha 正常失效。
- 预防：同时比较 opaque 动态屏幕与真正动态 mask 的缓存版本，并与完整实时路径逐像素对照；实例代理布局还必须包含 mobility，使用新 source/entry 对象测试静态与动态往返，避免旧引用掩盖规则变化。

## 运行状态不能把历史错误日志当作当前诊断

- 触发：Viewer 已恢复完整 GI，画面与动态设备正常，状态栏却一直提示模型几何不匹配。
- 原因：加载期静态源尚未到齐时产生瞬时失败；manager 后续成功应用并清除当前错误，但 Player 把最后一次 `pushLog` 永久存成显示状态。
- 修复：保留控制台历史，首帧真正就绪后读取当前光照诊断；恢复只移除该诊断，保留普通运行消息。Store 同步也不得覆盖真正的烘焙任务失败。
- 预防：验证部分源失败、全部源恢复、动态往返及静态真正失配；检查实际 Viewer 状态栏而不只统计 GI 代理数量、资产读取和运动。

## 阴影缓存按实际投影组汇集，不能按名义分组直接回退

- 触发：完整工厂的静态几何、投影和材质不变，但混合模式仍每帧重画全部静态阴影。
- 原因：原实现看到 renderList 含多个名义 rendering group 就回退；原生 ShadowGenerator 实际禁止组间深度清除，名义组也可能没有提交任何 submesh。
- 修复：在首个原生绘制回调中读取已 dispatch 的各组列表，按组汇集全部静态投射物，每个灯光面或级联只恢复一次缓存，随后累积各组动态。显式定制组间清理时保留完整原生顺序。
- 预防：首组动态/后组静态、首组静态/后组动态、每组混合、无效名义组都要与原生完整实时逐像素比较；覆盖点光六面、CSM、预深度和透明裁剪。关闭缓存的基准必须直接调用原生完整列表。

## 按需加载须保持脚本能力、资源来源和真实就绪边界

- 触发：Babylon 深层导入与脚本预转译降低首屏体积，手工 namespace/加载器白名单却遗漏既有 API、粒子注册或 glTF 1.0；scene inline 编译代码的自带 hash 也不能证明其来自原 TS。
- 修复：常见 API 精确导入，其余脚本按需取完整命名空间；保留原支持的 loader 版本，glTF2 用官方异步扩展工厂。预转译仅来自授权实际 TS 或随导出清单校验的独立 sidecar，绑定最终已复制源码 SHA，不执行 scene inline cache。
- 预防：用真实安装模块与普通 glTF 扫描契约核对支持范围；用同资产的全量/按需注册及预编译/原 TS 对照区分因果。脚本 onStart marker 早于场景资源准备，验收还须等加载遮罩消失、资源错误为空，不能只看 marker 或 pageerror。
- 本地恢复完成后，自动全库远端同步须等待真实中台配置；无地址时不把普通本地工程标为资源失败，显式同步仍保留配置提示。

## 动静合批须保留脚本查询语义并核对真正渲染边界

- 触发：工厂 LED 每帧通过 scene.meshes/getModelNodes 查询节点；从集合移出固定原件会改变脚本语义，整场景拒绝 beforeRender 又使所有设备合批失效。
- 修复：保留原对象、集合、层级和材料，通过公开渲染候选 provider 过滤固定原件，阴影 renderList 同步排除；候选核对后可能改状态的未知 observer、RTT、custom renderer、FrameGraph 和异步 Active Mesh 冻结均保守恢复原绘制。纹理签名必须包含实际 InternalTexture 身份，不能仅信任 data:#image0 等占位 URL。
- 预防：真实 Scene.render 验证主绘制和阴影不双绘、早期脚本可查原件、当帧改材质/几何/管线正确回退、取消后照明代理不复活旧高亮；NullEngine 的提交路径证据与实际 GPU 像素/FPS 分别报告。
- 可变GPU源：CPU数组未变也可能经公开buffer入口直接上传。按实际DataBuffer共享订阅，在上传前归还原件，通知使用快照；回调可能改绑ARRAY_BUFFER，委托原updateArrayBuffer前须恢复入口绑定。测试必须覆盖共享订阅者和真实GPU像素，不能只检查position数组。
- 同次遍历共享读取：相同实际Material或节点可在单次检查边界内去重；下一provider/RTT/mutation边界必须新读。serializer的导出字段不能误当live字段，实际嵌套纹理内容指针仍需进入签名。

## 阵列截图须等待所有参数变体就绪

- 触发：基础批次已就绪但临时参数宿主仍在执行脚本，截图 harness 把未绘制临时原件计入相机边界，产生 8 项新增视觉失败。
- 原因与修复：同 GPU 合批开关对照的 PNG 和相机完全相同，证明不能归因于合批；等待所有 variant measurementReady 且 externalScriptStarting=false，并在实际加载错误时立即失败，保持原阈值。
- 预防：固定资源、配置、相机、DPR、截图时机与业务就绪条件；保留无效轮次及基线原有失败，不能仅依据 marker、基础批次或 pageerror 为空判定可采样。

## 缓存须覆盖实际canonical输入而非仅按函数名称归因

- 触发：单Mesh几何缓存已有回归通过，真实工厂光照刷新仍在canonical数值编码上耗费大量CPU；同名递归hash不能说明实际输入。
- 原因与修复：按CPU profile父链及递归层数定位到独立的整组环境输入，而非primitive缓存失效；按Scene弱键只保留最新有序目录，保留原revision/key/positions/indices算法，每轮核对真实Geometry、buffer/type/layout及精确CPU值。未知读取器、非primitive revision和accessor目录回原表达式。
- 预防：用原表达式独立计算expected，覆盖fresh目录包装、无通知原地改写、顺序/key/revision/类型变化和释放。90,711值四轮仅首次编码证明组件工作减少；加载与FPS仍须用独立真实场景复测，不能把旧轮失败删除或把采样完成写成性能达标。

- 内部包装兼容：680个环境surface的原生读取仍因Hybrid包装顶层与dispatcher不相等而持续miss。只登记已知内部wrapper捕获的固定previous弱边，保持原回调body、调用/异常顺序和直接所有权释放；未知外部链继续回退。必须以真实tracker红测及实机摘要核对命中，不能仅信任组件绿测。
- 默认晋级：功能回归通过的23批/204逻辑原件，在当前镜头仅净少约5draw，四边界检查仍使1440p/4K更慢；保留显式实验并默认关闭。先按真实key逐维统计：706单例主要受728种实际几何内容约束，不能删除几何或安全条件，或把候选数直接当可见draw收益。

## 2026-10-22 P3 模块迁移中的回调 receiver

- 触发：将实例方法迁入 Controller，正文只替换 this 的成员路径。
- 原因：this.callback(...) 与 context.callback(...) 会把不同对象作为普通 function 回调的 receiver；仅归一化正文 tokens 会遗漏此差异。
- 修复：公共可选订阅继续保留原字段，在直接调用处恢复原 SceneRuntime receiver；原裸调用的环境通知继续裸调用，传给子运行时的原函数引用保持原样，optional call 保留短路。
- 预防：除方法体、构造/帧/释放顺序外，增加真实实例 function 回调 receiver、取消订阅不扫描以及异步失败通知回归。

## 2026-10-22 浏览器条件导出与验收夹具

- 触发：MQTT延迟加载的Node mock通过，真实浏览器报mqtt.connect is not a function。
- 原因：mqtt5.15.1的browser/import入口仅有default；命名mock和Node默认入口不能证明浏览器ESM形状。
- 修复：导入边界选择可调用connect的命名或default API，保留原对象、共享Promise和失败重试；传输/消息/驱动不改。
- 预防：直接传原生ESM namespace测试，并读取已安装browser入口做身份断言，再验证真实loopback MQTT。夹具与产品统一正式默认设置/持久化格式，探针使用相同direct模块，防止桶预构建产生第二个EngineStore。

## 2026-10-22 原生 TypeScript 测试须显式区分类型导入

- 触发：拆分后的文件在 Vite/tsc 构建通过，Node 原生 stripTypeScriptTypes 测试却报类型名称没有运行时导出。
- 原因：构建器依据使用位置删除类型导入；原生加载器仅依据显式 type 标记擦除，普通 import 中的 TypeAlias 会保留。
- 修复：追溯真实声明后给纯类型 specifier 添加 type；76项均为TypeAlias，20份文件生成的JavaScript逐字节相同，原生动静合批98项复验通过。
- 预防：模块搬移同时覆盖项目实际使用的原生TS测试入口，不能仅用类型检查或打包通过推断加载兼容。
- 独立编译图：自建临时tsconfig也必须包含正式全局声明及项目已有的扩展名重写约定；缺少vite-env.d.ts或rewriteRelativeImportExtensions会让正式构建已通过的真实模块图报TS2304/TS5097，不能靠降低strict或补虚假业务类型解决。
- 失败清理：runner以当前Node无shell执行编译与测试，保留真实非零exitCode并经过finally；编译失败不得启动后续测试，临时node_modules junction先解除，不能递归触达项目依赖。

## 2026-10-22 JSON签名不能替代原数据克隆

- 触发：清理Hook依赖时，用JSON签名解析结果替换原structuredClone草稿初始化。
- 原因：JSON只适合作为现有触发签名，合法数值-0会被编码为0；签名相同不代表原始数据类型和数值语义可互换。

## GLB 几何身份快照应按实际共享数据计量（2026-10-22）

## Babylon 静态工作副本不应保留逐顶点临时对象（2026-10-22）

- 触发：环境模型第一次应用前 JS 主堆已约3.67GB，但 TypedArray backing 仅约165MB、DOM约3000节点；共享数据快照修复后仍崩溃。
- 原因：堆采样将约3.48GB存量定位到 `Mesh.clone → refreshBoundingInfo(true,true) → AbstractMesh._getData`。Babylon9.12为各clone保留完整 POSITION 的 `_internalAbstractMeshDataInfo._positions`（Vector3数组），不是Geometry拾取缓存，也不是DOM或重复BRDF。
- 修复：只在环境工作副本的静态源克隆期间注册临时 `onClonedObservable`，每个clone完成原生包围盒计算后及时释放该clone的可重建位置缓存；不动源、几何、材质和包围盒。骨骼、morph和baked顶点动画保持原行为，监听在finally归还。
- 防止复发：同时记录JS heap、backing、DOM及分配调用栈，不能只凭RSS推断来源。回归覆盖逐clone保留量、原数据/包围盒、幽灵材质、形变排除及异常清理；单clone峰值只对应实测平坦结构，不承诺任意层级模型的绝对上限。
