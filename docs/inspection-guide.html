分别配置三处，先跑通一台设备

教程使用输送设备作为示例；名称、编号、类型和节点路径都应换成实际数据。

01

模型管理：一份低模，一份高模

位置：数据中台 → 模型管理 → 新增或编辑模型。

字段场景低模示例爆炸图高模示例
模型名称输送设备 · 场景低模输送设备 · 分件高模
模型编号CONVEYOR-LOW-01CONVEYOR-HIGH-01
模型用途场景低模（SCENE）爆炸图高模（INSPECTION）
设备类型选择同一个字典项，例如“输送设备（conveyor）”
文件 / meta原有场景资源及其参数配置自包含 GLB/glTF + 包含 inspection 的完整 JSON
  1. 先登记低模。

    用途选择“场景低模”，填写唯一模型编号，并选择真实设备类型。

  2. 再登记高模。

    使用另一模型编号，用途选择“爆炸图高模”，选择相同设备类型，上传保留分件节点的高模文件。

  3. 核对“设备类型”和“模型类型”。

    设备类型是业务字典编码 conveyor；模型类型可能是 glb。匹配时使用真实编码，区分大小写。

高模必须真的可分件。一个整体网格不能自动拆出内部零件。纹理和缓冲区须内嵌；含外部 .bin、图片或资源 URL 的 glTF/GLB 会被拒绝。高模首期按静态装配展示，不执行低模参数脚本。
02

在高模中维护 meta，随版本入库

位置：模型编辑弹窗 → 版本元数据。

  1. 选择维护方式。

    不改规则时选“保留现有”；已有文件选“上传 JSON”；需要修改选“编辑 JSON”。上传后还可以继续编辑。

  2. 填入完整 JSON。

    保留原有字段，再加入 inspection.schemaVersion: 1 和非空 parts。节点路径必须来自当前高模。

  3. 点击“校验元数据”，再保存。

    校验通过会显示零件数量。修改 meta、用途或高模设备类型会产生新版本，已固定的旧版保持不变。

模型制作人员提供

  • 每个零件的稳定 partKey 和名称。
  • 真实节点路径 nodePath。
  • 世界方向 axis、米制距离和固定状态。
  • 必要时提供适用配置与完整参数快照。

配置人员确认

  • 高模与低模设备类型一致。
  • 零件标识、节点路径各自唯一。
  • 单位正确，展开后方向和距离合理。
  • 当前固定版本确实适用于这类设备。
展开查看可下载的 meta 示例

字段怎么填写
lengthUnit放在 meta 顶层。支持 meter/m、centimeter/cm、millimeter/mm；普通模型缺省米。
partKey稳定装配位标识，例如 drive.motor；业务记录和接口用同一个值。
nodePath“.”代表加载根；其他路径不含加载根，按 / 逐级连接。同级节点名需唯一，不用空段、. / .. 段、逗号、分号或换行。
axis非零世界方向，如 {x:1,y:0,z:0}。数值必须有限。
distanceMeters / fixed距离是非负米数；固定组设 true。文件是毫米单位时，展开距离仍按米填写。
parentPartKey可选，引用清单内已有零件且不可循环；不会改变模型实际节点层级。

实际可移动父节点会带动整条子分支，后代不再重复叠加位移。固定父节点下的后代保持固定；可移动祖先与固定后代冲突会被拒绝。

同类型、不同尺寸时要核对适用性。可选 inspection.configuration 包含 id 和 parameters，parameters 必须与低模当前完整参数快照一致；缺失或不一致会阻止加载。省略时按类型使用，系统不会推断真实尺寸。当前一个按钮对每个设备类型只能配置一个高模版本，不会按参数自动选多个版本。

旧记录只有 meta 文件链接时，需显式上传或粘贴 JSON 并保存新版本；打开旧模型不会自动回填数据库。

03

编辑器只准备低模与设备身份

位置：数字孪生编辑器 → 已绑定中台的工程。

  1. 同步场景低模。

    普通模型库读取“场景低模”。把低模用于主场景，高模不必拖进场景。

  2. 为设备实例填写资产编号。

    例如 CV-021。编号用于设备选择和定位，应与业务记录一致，并能够精确定位。

  3. 同步设备类型，保存并重新发布。

    中台的 deviceType 随低模资源同步进入场景；旧实例没有类型时需同步并重新保存发布。已有旧 Viewer 不会因只升级中台而自动获得新能力。

这一步不填写高模零件 JSON。新流程不要求配置“高精度详情”绑定，也不要求“打开设备详情”或“展示图表”点击效果。默认点击、仅高亮和显式聚焦都可以传递当前设备上下文；ignore 仍保持忽略。

如果设备点击还需要打开一个子大屏，仍使用原来的“展示图表”配置。子大屏内的爆炸图按钮读取来源场景当前设备，目标 Runtime 不能指向另一个不相符的场景。

两个编号不要混用

assetCode 是场景设备资产编号；namespace 和 deviceNo 是可选业务身份。按类型打开爆炸图只需要真实设备类型，不要求这两项，系统也不会用 assetCode 伪造它们。业务接口如果要求这些字段，须先配置真实对应关系。

04

大屏按钮：点击动作选择“爆炸图”

位置：大屏设计器 → 按钮组件属性；按钮组则选择对应子按钮。

同项目中的大屏放什么组件怎么关联
主大屏 A · 厂区总览数字孪生 Runtime来源选择当前项目发布或历史发布
子大屏 B · 设备操作爆炸图按钮、设备指标；可没有 Runtime按钮目标选择“厂区总览 / 厂区三维场景”
  1. 让两块大屏归属同一个项目。

    在主大屏 A 准备 Runtime；按钮大屏 B 可以没有 Runtime。旧的手填 URL 不具备明确项目归属，不会进入项目候选列表。

  2. 在 B 添加按钮并设置点击动作。

    按钮文案可填“设备爆炸图”，点击动作选“爆炸图”；按钮组选择需要配置的子按钮。

  3. 从当前项目选择目标 Runtime。

    列表按“所属大屏 / Runtime 名称”展示，选择 A 的场景。候选包括项目中其他大屏，不再只看按钮所在大屏。

  4. 添加设备类型映射。

    依次选择设备类型、高模和固定版本。可以按模型名称搜索；每个类型只留一行。

  5. 保存并从主屏验证。

    从 A 打开展示，把 B 作为其中的引用内容页或设备点击打开的浮层。先在 A 选中设备，再点击 B 的按钮；确认正确后发布大屏。

项目内可选，不代表目标已运行。运行时使用当前主屏里已加载的 Runtime。单独打开 B，或只在另一个浏览器标签页打开 A，不共享场景与设备选择；请从 A 的展示入口打开 B。
以后升级高模：上传 V2 后，原按钮仍打开 V1。要切换，回到该映射明确选择 V2，再保存并重新发布大屏。只改高模 meta 也需要这样更新引用。
配置保存在哪里？复制后会换目标吗？

目标保存为 data.digitalTwinRuntimeTarget={projectId,screenId,widgetId}，项目和大屏 ID 为字符串 Long；这能区分不同大屏中恰好同名或同 ID 的组件。高模映射另存为 data.inspectionAction={schemaVersion:1,mappings:[{deviceType,modelId,versionId}]}；按钮组保存在 data.items[*].data。

同项目复制或克隆保留这个明确目标。带目标的按钮屏换项目、解除项目关联或跨项目克隆前，需要先清除旧目标，再重新绑定。仅被引用、没有参与克隆的其他大屏保持原样。旧按钮的本屏目标与来源场景自动绑定保持兼容。运行时设备身份、URL 和完整 meta 不写入按钮。

05

先点设备，再点爆炸图

高模按需加载；正确加载后自动展开至 100%。

  1. 选中场景中的设备。

    例如 CV-021；大屏取得当前设备的真实类型。

  2. 点击“设备爆炸图”。

    大屏匹配类型，读取已固定版本及其 meta，打开独立 Babylon 详情。

  3. 展开、选择和查看。

    用滑块调整 0–100%，在零件树或模型中选零件，使用聚焦、隔离与复原。关闭时释放高模详情。

联动零件指标

指标、告警、维修记录使用大屏已有组件。数据源选择“仅传递声明参数”，声明实际需要的 assetCode、partKey 等字段，并按需要设为必填。

如果只按资产编号与零件查询，就不必声明 namespace/deviceNo。必填字段缺少时不会请求，旧值会隐藏。

表格反向定位

表格开启“记录定位设备零件”，配置“设备资产编号字段”和“零件标识字段”，例如 device.code、part.key，值应为非空字符串。

同设备已打开高模：可复用详情定位零件。跨设备：先选择设备、点击爆炸图打开相应固定版本，再点记录定位；不会猜测其他按钮的映射。

展开程度、相机和隔离状态只影响查看，不写回场景，不触发零件业务查询。切换设备、取消选择或重载场景会使旧详情和迟到响应失效；关闭详情清除零件上下文，仍有效的设备上下文保留。

HTTP Body 或流程参数映射发生在声明字段过滤之后，不能恢复被过滤的 partKey。流程结果集只是读取既有快照，不会自动按零件过滤或重跑。详情弹窗没有内置业务指标区。

核对

配置完成后，按这几项验收

先在一台设备上确认，再推广到同类型设备。

  • 低模和高模编号不同、用途正确，deviceType 完全一致。
  • 高模 meta 校验通过，文件可分件且资源内嵌。
  • 场景设备资产编号正确，已同步类型并用新版 Viewer 重新发布。
  • 按钮指定有效 Runtime，类型映射和固定版本完整。
  • 先点设备再点按钮，能打开正确高模并自动展开。
  • 点不同零件时，实际请求携带正确 partKey；旧数据显示被清除。
  • 关闭、换设备、再次打开时，不混用上一次模型或零件。
  • 上传 V2 后，未修改映射的已发布大屏仍加载 V1。
按钮屏没有 Runtime，应该从哪里选择？

先确认按钮屏与主屏属于同一个项目，再在“项目中的目标 Runtime”中选择“主屏名称 / Runtime 名称”。目录列出项目各大屏的有效场景；如果列表为空，检查主屏是否已保存，以及 Runtime 是否绑定了该项目的当前发布或历史发布。

已经选到目标，却提示目标未加载或来源冲突？

请从承载目标 Runtime 的主屏打开按钮子屏，等待场景就绪并重新点击设备。独立打开子屏、另开标签页，或只引用主屏的普通组件，都不会带来其 Runtime。设备点击打开的子屏还会核对来源；按钮绑定的场景应与打开它的场景一致。

没有选设备就点按钮，会怎样？

会提示先选择设备。选中设备后再点一次即可；不会拿上次的设备或任意高模凑数。

提示没有 deviceType，或未配置该类型映射？

核对中台低模的设备类型；重新同步、保存和发布场景。再检查按钮中是否配置该编码，注意大小写，不要用 glb、中文名称或遥测枚举替代。

版本不可用，或高模不在下拉列表？

确认用途是爆炸图高模、设备类型正确、meta 已入库。旧版本缺少冻结元数据时，显式保存新版本并重选；列表可按名称搜索。高模不会自动回退最新版本。

提示参数配置不适用？

检查 inspection.configuration 的完整 parameters 是否与低模当前参数一致。应选择确实适用的模型/版本；不能靠删除约束让错误几何通过。省略适用配置时需由维护者验证实际尺寸和零件结构。

零件不移动，或展开方向不对？

检查实际节点路径、分件结构、世界方向、米制距离和 fixed。父节点已经移动时，子分支不会再叠加自身距离；parentPartKey 只声明关系，不重排真实模型层级。

选了零件，但指标没有变化？

确认接口支持按零件查询，在“仅传递声明参数”中包含 partKey，并映射到真实请求。必填字段必须实际存在；0 和 false 有效，空白、null 和缺失无效。

为什么不能删除高模或跨平台导出项目？

草稿、所有保留发布快照及冻结子屏会保护高模引用，需先处理这些引用。当前项目 JSON 与完整归档不支持大屏固定高模版本跨库重映射，会明确拒绝迁入/迁出，不会悄悄遗漏模型。

断网能不能看？旧场景怎么处理？

这份教程可离线阅读。新按钮流程在线读取中台高模和 meta，不自动把高模打入场景离线包。旧场景的显式高模绑定和原有发布资源规则保持兼容，新项目按本教程配置即可。
