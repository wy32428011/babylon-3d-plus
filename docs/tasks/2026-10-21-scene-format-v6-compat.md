# 场景格式 v6 打开与发布兼容修复

## 目标与边界

用户反馈统一光照改造后，打开场景在资源准备阶段报 `场景模型更新格式无效。`。修复所有受影响的场景格式入口，保留原有资源准备、业务数据和校验；不降级文件，不跳过环境/模型就绪，不修改用户场景，不上传或发布。

## 证据与假设

1. **已确认**：保存器输出外层格式 6，但 `prepareLocalSceneResources` 仍只接受 1–5。仅把既有合法集成夹具改为 6，真实 Electron 立即抛出相同错误；见 `output/scene-open-v6/local-scene-red.log`。
2. 其他主进程入口版本白名单遗漏可能在工程包打开、发布身份/模型恢复或快照准备阶段复现。只读检查已发现五处拒绝 6 的门禁。
3. 场景本身损坏或模型资源缺失：不是上述夹具失败原因；修复后仍保留原有 JSON、实体与资源验证以辨别此类问题。
4. 旧 Electron 进程可能继续运行旧主进程：交付时区分源码/构建与已运行用户窗口，不关闭未确认保存状态的用户实例。

## 方案与验收清单

- [x] 统一共享当前场景版本和支持判断，编辑器、主进程、工程包与发布使用同一合同。
- [x] version 6 经真实 Electron 本地资源同步通过，保留普通/组合/环境模型权威刷新和就绪检查。
- [x] 既有 1–5 兼容；未知 7、字符串版本与无效结构继续拒绝，读取预处理不得将未知版本改写为 6。
- [x] 发布模型就绪、身份恢复、入口/非入口场景快照准备接受 6，保留业务字段和原始文件。
- [x] 实际配置本地接口后通过 IPC 打开 v6 场景，观察初始化和首帧；不以无接口路径替代资源准备。
- [x] 聚焦回归、完整类型/Editor/Viewer 构建、代码审查完成；文档和任务记录更新，资源回收。

## 当前状态

已完成。共享 `sceneFileVersion.ts` 及 14 个消费者使用同一版本合同；所有修改只涉及外层场景格式兼容。既有统一光照/GI、设备驱动、材质/阴影引擎改动保持原状。
