1. 缓存增加仅持有模板的预取 lease，复用并发、取消和引用计数。
2. 生成器预取协调器管理默认/规则/组合目标、配置代次和准备等待；实际货物仍走原生成路径。
3. 连接加载调度、进度与 Editor/Viewer 就绪；组合阵列成员也复用已预热的独占模板克隆。
4. 验证首次生成、异常与取消、脚本隔离、交接和硬件画面，审查并归档。

## 证据与决策

- `SharedModelAssetCache` 已有按资源修订解析去重；预取持有活动引用，生成器释放时归还，空闲仍受原预算限制。
- `loadModelRuntimeAssets` 会实例化/克隆，不能用作纯预取；新增预取入口仅加载并准备模板。
- Editor 普通准备直接调用 `waitForSceneRenderReady`，Viewer 经过 `SceneRuntime.waitForInitialRenderReady`；两端必须统一等待当前预取。
- 组合中的阵列源目前直接调用 `loadAssetContainer`，需接回既有独占容器缓存路径，避免预取后再次解码。
- 预取只提前支付加载/解码成本，不承诺累计耗时为零或指定 FPS；不实现对象池及动态 ThinInstance 槽位池。
