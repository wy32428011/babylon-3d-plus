# 时光回溯：可配置数据源专项计划

## Context

现有总方案已定义后台采集、完整状态投影与 Viewer 回放，但数据源仍主要以引用字段出现，尚未形成可配置的产品与服务合同。用户本轮明确选择 **“两者都支持”**：既可使用本平台持续采集生成的历史，也可使用外部业务系统提供的历史接口。

本专项沿用完整设备/动态设备/货物/库位/告警回放、编辑器统一配置、后台持续运行、Web Viewer 只读回放、千台高频及数月保留要求。不把 MQTT 最新值、普通库存查询或图表时间过滤冒充历史源。数据源与历史系统仍处于方案阶段；已确认的独立 UI 原型只用于视觉与交互评审，不表示业务功能已实现。

## 已确认的推荐范围

- 编辑器“时光回溯设置 → 数据源”支持两种明确提供方：本平台历史、外部历史接口。
- 本平台历史：可配置 MQTT/只读 HTTP 采集输入及完整初态来源，后台形成与场景版本绑定的历史。
- 外部历史：配置服务端代理访问的历史接口、认证引用、参数/字段映射和能力合同；不得只填一个 URL 就标为完整可回放。
- 两种提供方在 Viewer 前统一为覆盖范围、目标时刻全态、后续变化、关键事件、质量及版本的查询合同。原始事件型外部源与完整状态型外部源必须区别接入。
- 一次回放会话固定一个提供方/修订及场景版本，不自动混拼两个来源的同一段历史，也不在外部请求失败时静默替换为平台数据。
- 凭据和来源注册由服务端管理；场景与发布包保存无密钥引用。编辑器是配置入口，不是长驻采集或历史转存进程。
- 不包含数据库驱动直连、任意 SQL、日志文件导入或通用连接器平台；这些不是“两者都支持”所必需。

## 一、推荐配置模型

### 1. 明确四种角色，避免一个 URL 承担全部职责

| 角色 | 本平台历史模式 | 外部历史接口模式 |
|---|---|---|
| 历史提供方 | 当前项目的后台历史服务，自动解析平台地址 | 服务端登记的外部 HTTP 历史源，经中台适配后读取 |
| 持续采集输入 | 一个或多个 MQTT / 只读 HTTP 输入，记录设备及业务变化 | 不要求额外把外部数月历史整库复制到本平台 |
| 初始基线 | 设备、库存、持货/在途任务及必要告警初态与增量交接点 | 外部可定位的完整基线及之后的有序历史事件；由相同状态内核恢复 |
| 返回实时 | 当前场景已激活的 canonical 实时状态服务 | 同样重新握手当前 canonical 实时服务；不把外部“最近一条历史”冒充实时 |

一次历史会话绑定 `providerId + providerRevision + upstreamSnapshotRevision + publishedVersionId + projectionId`。一个提供方可包含互补的多个输入，但每个业务实体/字段须有明确权威来源；相同角色/设备域重叠时预检阻止应用，不按“最后响应赢”随机覆盖。不自动混拼两个提供方的同一段历史，也不自动故障切源。

### 2. 存储与配置边界

- 复用总方案的 `HistoryReplaySettings`、来源绑定与 `SourceContractSnapshot`，增加无密钥 `historyProviderRef`；场景只保存来源 ID、精确修订与用途引用，不再复制一份可漂移的连接配置。
- 服务端管理来源定义草稿、不可变修订、认证引用、能力及可用状态；来源的 ID/修订与采集策略 revision、场景绑定 revision 分开。
- 本平台模式的采集与基线绑定属于同一已锁定来源配置。复用现有 MQTT/Fetch 时，将有效配置解析为候选快照供确认，不直接“永远跟随最新”。
- HTTP 注册/执行优先复用中台已有能力；MQTT 若没有独立服务端连接注册，只在历史模块补所需的连接定义，不把通用数据源平台重写一遍。
- 所有业务 ID、来源 ID、游标、大序号按字符串传输。订阅绑定使用稳定 `bindingId`，不能用数组下标或临时 MQTT clientId；编辑器已有 `adapter.sourceId` 可复用并明确展示。禁用或退役来源保留被历史引用的修订；被有效采集引用时不允许无提示硬删。

### 3. 已核实的复用边界

- `Toolbar.tsx` 已有 MQTT 订阅/EPV/JSON Path 和 `parseDeviceTelemetryMessage` 样例解析；Fetch 只有 `url/apiKey/syncIntervalSeconds`，不存在现成的历史来源选择器。`EffectDataBindingInspector.tsx` 的托管来源仍为手填 ID，可借鉴映射与样例交互，不能当已完成目录组件。
- 中台 `DataSourceAppService` 可复用 HTTP 模板、认证注入、脱敏元数据和请求准备；现有 `fetchHttpJson(id, runParams)` 每次读取可变配置，不能直接执行已冻结历史合同。现有列表无项目授权过滤，`updatedAt` 也不是已实现的并发 revision。
- `test` 会访问上游并写测试记录，`inferSchema` 在没有成功样例时同样会发请求；打开弹窗、选择来源或查看详情不得自动调用它们。样例推断只能辅助选字段。
- `JdkDataSourceHttpClient.execute` 使用 `BodyHandlers.ofByteArray()` 整体接收，未执行 `maxResponseBytes` 限制；`paginationJson` 的存在也不表示 Fetch 已能完整分页。历史链路必须新增实际限流/取消/分页预算，不能复用字段后宣称已有保护。
- 现有独立桥 `effectDataContract.ts` 只允许当前 HTTP 取数与 MQTT latest，不能传历史范围/游标或源目录管理。新增独立白名单历史 IPC，不把该桥扩成任意 URL 代理。
- 新历史凭据由历史模块受控管理，不能登记为可被匿名通用 Fetch 调用的新数据源。引用既有 HTTP 来源时，需要可信入口同时约束其通用取数旁路及来源权限；未具备该边界时仅允许配置草稿，不声称项目隔离已经成立。

### 4. 旧 Fetch 配置的安全衔接

现有 `FetchConfig.apiKey` 会随普通场景序列化，必须将“复用配置”与“复制密钥”分开：先经明确操作将凭据托管到服务端，建立受控引用取数路径，再对启用历史的场景应用无密钥引用；迁移失败不清除旧值、不破坏原预览。新历史发布在 SOURCE/DIST 导出边界检查旧 `apiKey` 及敏感 Header/URL，未完成迁移则阻止发布。未启用历史的旧场景不自动改写，旧凭据也不自动上传。

## 二、编辑器交互与可配置字段

入口固定为 **工具栏 → 时光回溯设置 → 数据源**；发布弹窗展示引用、预检与生效摘要，不维护另一份表单。

### 配置流程

`选择提供方 → 选择/新建来源 → 配置连接和用途 → 映射字段 → 读取受限样本 → 服务端预检 → 保存场景草稿 → 发布并显式激活`

- 数据源列表提供名称、类型、所属项目、修订、覆盖范围/数据质量、使用中的场景与连接状态；提供选择、创建、编辑草稿、复制配置、测试与预检入口。复制不复制有效启用状态或默认导出凭据。
- 来源详情按模式显示相关表单；外部模式不展示无关 MQTT 采集启停按钮，本平台模式不要求用户手填平台历史查询 URL。
- 单独显示“已保存草稿、连接通过、映射通过、完整性通过、已发布、已激活、可查询范围”；HTTP 200 或收到一条 MQTT 消息不等于完整回放就绪。
- 未绑定平台/离线时允许保存无敏感草稿和使用脱敏样本校验映射；远端注册、测试、预检和激活禁用并说明原因。已有有效配置继续工作。

| 配置区域 | 主要字段及约束 |
|---|---|
| MQTT 采集 | 来源名称/稳定 sourceId、服务端 broker 地址与协议、TLS/认证引用、topic 过滤器、QoS、解析适配器、设备身份与时间/序号映射、完整帧/增量语义；生产 clientId/会话与恢复策略由服务器管理。浏览器 WebSocket 地址不直接当服务器 TCP 地址 |
| HTTP 采集 | 现有数据源/接口引用或受控新建连接、GET/POST、受限模板参数、数据提取路径、轮询/业务触发规则、超时/重试与响应预算；明确只读性、全量/增量与空结果含义 |
| 基线来源 | 按设备/库存/在途等用途绑定接口；必需字段、资产/库位/货物映射、全量范围、版本与增量衔接游标。多来源必须可对齐，不把不同时间的多个响应冒充一个原子全态 |
| 外部历史 | 基础地址/现有 HTTP 来源引用、认证引用、覆盖范围/基线/事件查询接口、参数位置与模板、响应提取、时间单位/时区、稳定排序和分页游标、源数据修订/封闭水位、设备与场景版本区间映射 |
| 字段映射 | 项目/来源身份、设备类型与编号、货物/任务身份、时间与序号、事件类型、状态/位置及单位、库位行列层；复用受控解析/映射，不开放任意服务端 JS |
| 凭据 | 沿用服务端认证或受控登记新凭据；只写入，不回显。区分保持、替换、清除，遮罩字符串不能覆盖真实密钥。场景、样本日志、SOURCE/DIST 不保存凭据 |

“设备、动态实体、货物/库存、告警”使用能力覆盖表，而不是强制每类各填一个 URL；同一输入能满足多类能力时只绑定一次。缺少完整回放必需能力显示阻塞，不提供静默降级的勾选项。

## 三、外部历史接口的首版接入合同

推荐首版采用 **可定位的全态基线＋有序历史事件**，由中台适配、同一业务状态内核和检查点机制提供统一查询；外部系统不必实现 Babylon Mesh 或浏览器专用内部对象。仅有设备数值曲线、聚合均值或当前库存的接口不能通过完整回放预检。

| 接口职责 | 必须提供的信息 |
|---|---|
| 覆盖与修订 | 可用时间区间、缺口、稳定数据集/快照修订、完成水位、支持的设备/业务范围、分页及请求预算；无法提供完整区间证明时保持未就绪 |
| 历史基线 | 指定时刻或之前的有效全态、实际基线时间、覆盖范围、数据修订及之后可接续的事件游标；不得返回当前状态并贴上历史时间 |
| 历史事件 | 指定范围内稳定排序、分页可续传的完整输入，稳定事件身份、源纪元、事件/观测时间与全量/增量语义；时间边界统一为 `[from, to)`，同毫秒不能丢事件 |
| 关键事件 | 能由已归一化输入派生则由平台生成，不强制外部另实现一套告警/事件索引接口 |

- 页面分批读取期间固定同一上游快照修订（或同一不可变日志上界）；响应修订变化、游标失效、乱序或缺失必要字段时中止当前准备，不把不同批次拼成一个全态。上述是接口职责，可以由一个 API 的不同参数承担，不强制供应方提供多个固定 URL。
- 时间轴口径随来源修订锁定：平台观测时间与外部事件时间分别标明，外部请求的 `fetchedAt` 只作取证时间，不能替换历史时间；时间单位/时区、迟到和同刻排序规则必须一致。字段映射不能补造不存在的业务事件、初态、分页完结证明或数据修订。
- 先按配置转换为总方案的历史事件与逻辑基线，再建立版本化的投影/检查点。准备范围必须包含有效基线到目标时刻的全部必要事件以及窗口开始前尚未结束的业务关系；距离过远或超预算则显示未准备，不能省略事件。第一次访问明确显示进度和可查询水位，不在浏览器从月初重演或承诺首次任意时刻立即定位。
- 请求与解析有时间、页数、字节和实体预算，支持取消及同请求身份重试；错误、超限与合法空结果区分，失败不清空已有有效库存。
- 只持久化实际消费窗口的必要输入证据、投影与检查点，不默认整库镜像；外部原始历史保留责任仍在上游。界面分别显示上游可提供区间与本地已准备区间，不能用缓存冒充数月完整归档保证。
- 外部版本区间必须映射到已保留的场景/逻辑版本，禁止默认拿最新版布局解释所有旧数据。外部源不支持必需初态或衔接合同则保持配置可保存但不可激活。
- 返回实时仍遵循总方案的完整当前态＋游标握手。外部仅有历史能力时不据此禁用或替换当前实时来源；缺少可用 canonical 实时绑定时不能宣称完整交互闭环已就绪。

## 四、生效、预检与共享引用

- 连接测试和解析样本预检都不启用长期采集。MQTT 测试使用隔离的临时订阅身份、限时限量且禁止 publish；HTTP 只访问已批准的只读接口，使用只读凭据，不自动调用可能含发送节点的数据流程。历史执行单独落实允许目标及重定向校验，不能把现有默认 `allowed-hosts=*` 当成限制；只保存必要的脱敏诊断，不写入生产业务历史。
- 服务端预检依次检查授权/项目归属、实际网络可达性、协议/映射、身份冲突、覆盖与初态衔接、版本匹配、容量/查询预算；返回阻塞原因、影响场景与验证摘要。
- 预检先解析并冻结候选 `SourceContractSnapshot`，返回合同 ID、摘要、有效期、阻塞项和影响范围；随后发布绑定该摘要，激活再次核验来源、权限及预期策略/绑定 revision。相关配置改变使结果失效，不能在预检后读取已被修改的全局注册行。冻结合同是预检的内部步骤，不增加一套要求用户手工操作的配置。
- 修改来源或数据语义生成新修订，经发布和显式激活后才切换；准备失败保留旧有效配置。切换关闭旧绑定区间，建立新基线/投影代次，并保留旧历史的来源修订与版本入口。**选择外部历史只切换回放绑定，不隐式启动、暂停或删除已有平台采集。**
- 来源远端保存与场景本地保存分开提示；取消弹窗只丢弃未应用的本地编辑，不删除已保存的远端来源，撤销场景命令也不回滚已激活服务器配置。
- 凭据正常轮换与留存/资源策略分别处理，不冒充业务历史版本变化；若认证变化同时改变租户/数据域，则必须按新数据合同处理。
- 生命周期操作明确分开：“停用新绑定”不影响既有运行；“暂停采集”提示共享场景并记录缺口；“撤销连接访问”停止后续上游请求；“删除”只允许无有效/发布/历史引用的草稿或修订。凭据撤销与当前访问策略优先于冻结合同，不能借旧快照绕过禁用。
- 外部源被撤销访问或删除上游数据时如实显示不可用，不自动改接另一来源；已经独立保存的证据按本平台保留/读取授权处理，不能据此宣称未下载区间仍可用。无长期可用性保证的外部源不得被标成平台已托管的长期归档。
- 管理操作仍依赖总方案的受限项目授权/可信入口；现有匿名登录、namespace 和发布 targetToken 不承担新权限。Viewer 只获得限项目/时间范围的读取能力，不能任意指定 URL、凭据或执行源探测。

## 五、服务合同与实现落点

### 历史专用 API（拟新增，POST 动作接口）

前缀沿用 `/api/v1/twin-history`；目录/配置接口返回白名单脱敏 DTO，不代理任意 URL，不直接暴露现有全局数据源列表。

| 接口 | 职责 |
|---|---|
| `/sources/query`、`/sources/detail` | 按项目授权查询来源/可用修订、角色、能力、引用关系和状态；只读元数据，不自动探测上游 |
| `/sources/draft/save` | 以幂等 requestId、expectedRevision 保存服务器来源草稿及明确凭据操作，不启用采集；既有 HTTP 来源解析为候选，新增 MQTT/历史专用 HTTP 定义在受控历史域内保存 |
| `/sources/probe` | 显式执行限时限量连接/样例读取，支持取消及 generation；结果脱敏，成功不等于完整性通过 |
| `/capture/config/validate` | 沿用总方案，扩展为按提供方解析候选合同、校验角色/初态/版本/预算；平台与外部复用同一校验结果模型 |
| `/providers/activate` | 对已发布版本显式激活历史提供方，准备外部窗口/基线后原子切换绑定；平台模式复用既有采集激活任务，外部模式不创建 MQTT 采集器。共用绑定 revision、幂等任务及提交协议，不再建立第二份有效配置 |
| `/sources/usage`、`/sources/retire` | 展示影响及停止新引用，拒绝破坏有效/保留期依赖的删除；暂停采集继续使用总方案的专门操作 |

数据读取继续使用统一的 `/coverage`、`/sessions/open`、`/state/at`、`/changes/query` 和关键事件接口。Viewer 请求来源引用及会话，不携带外部地址/认证；服务端按固定合同选择提供方。缓存键包含项目、合同、上游修订、场景/投影版本与读取权限，禁止跨源、跨项目复用状态。

## 六、最小端到端验证与交付边界

数据源规划仅进行了源码/合同静态核对，没有调用上游接口；已确认 UI 的原型检查只覆盖模拟控件与视口，不替代真实历史链路验证。实施后针对以下实际风险验证，不默认新增测试文件或运行全仓检查：

- **真实编辑器配置：** 使用实际编辑器/浏览器预览工具完成两种提供方选择、新建/引用、字段映射、取消、一次撤销、保存重开、离线草稿及错误提示；查看控制台/网络并留必要截图。打开目录不触发 test/infer-schema、上游请求或采集启动。
- **本平台来源：** 受控 MQTT＋只读库存接口产生设备、动态实体、货物/库位和告警变化；验证服务端预检、完整初态接续、显式激活、关闭编辑器后继续采集，以及统一状态查询。
- **外部来源：** 使用有明确合同的只读外部样本/测试环境，覆盖稳定分页、同毫秒多事件、基线之前仍在途状态、源时间单位/时区、快照修订变化、超预算与取消。与来源业务记录核对目标时刻状态；普通最新值/聚合曲线、无完整初态或无分页完结证明的源必须被阻止激活。
- **生效与安全：** 预检后来源变化、并发 revision 冲突、超时重试、切源失败保留旧绑定；项目越权及绕过历史接口的通用取数路径被拒绝；普通模式不会因选择外部源被误停采集。检查场景/SOURCE/DIST/样例日志无新旧绑定泄露的密钥，遮罩值不覆盖凭据。
- **回放接续：** 两种来源都经统一 snapshot/changes 合同运行；缺口不当空库存、不自动混源、旧回调失效；返回实时重新取当前有效版本全态＋游标，不把外部最后一条记录当实时。

外部接口文档/样本、历史保留 SLA、基线及增量一致性证明目前尚未提供，因此这里只承诺明确的首版接入合同与配置路径，不保证任意外部 API 都可仅靠填 URL/字段映射完成完整回放。具体容量和响应预算沿用总方案的真实规模确认门槛。
